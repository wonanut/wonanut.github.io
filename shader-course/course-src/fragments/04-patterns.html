UV 图案：step、fract 与棋盘 把连续坐标切成格子，是所有程序化图案的起点

棋盘、条纹、点阵、网格——看起来不同的图案，底层都是同一组操作：放大 UV、取小数部分、判断奇偶、用 smoothstep 画线。

01把空间切成格子

核心操作只有两个：uv *= n 放大坐标，fract(uv) 取小数部分。放大后每个整数区间变成一个格子，fract 把它们折叠回 0..1。floor(uv) 则告诉你当前在第几个格子。

vec2 uv = vUv * vec2(uRes.x/uRes.y, 1.0) * 8.0;
vec2 g = abs(fract(uv) - 0.5);             // 到格子中心的距离
float checker = mod(floor(uv.x) + floor(uv.y), 2.0);
float line = smoothstep(0.49, 0.5, max(g.x, g.y));

checker 为 0/1，用来选两种底色；line 在靠近格子边界时接近 1，用来画网格线。两者叠加就是一个会动起来的棋盘。

像地砖的铺法

放大 UV 相当于决定每块地砖多大；fract 是「你在这块砖里的哪个位置」；floor 是「你在第几行第几列」。改砖的大小、颜色和缝隙，就能得到完全不同的图案。

类比到哪为止：真实地砖有物理缝隙；shader 里的「缝隙」只是 smoothstep 画出来的一条颜色带。

02完整片段

precision highp float;
varying vec2 vUv;
uniform vec2 uRes;
uniform float uTime;

void main() {
  vec2 uv = vUv * vec2(uRes.x/uRes.y, 1.0) * 8.0;
  uv += vec2(uTime * 0.08, sin(uTime * 0.3));
  vec2 g = abs(fract(uv) - 0.5);
  float checker = mod(floor(uv.x) + floor(uv.y), 2.0);
  float line = smoothstep(0.49, 0.5, max(g.x, g.y));
  vec3 col = mix(vec3(0.02,0.04,0.08),
                 vec3(0.08,0.5,0.55),
                 checker * 0.35 + 0.1);
  col = mix(col, vec3(0.75,0.9,0.95), line * 0.65);
  gl_FragColor = vec4(col, 1.0);
}

03抗锯齿

当格子很密时，一条像素可能跨过多个格子，硬边会出现摩尔纹和闪烁。WebGL 1 没有内置 fwidth，但可以用两个 smoothstep 控制线宽，或降低图案频率、加一点模糊。先把图案做「粗」一点，通常比事后抗锯齿更有效。

🔬 深入：为什么放大 UV 会让边缘闪烁？

因为像素是离散采样。当图案频率接近像素频率时，采样结果会在不同帧/不同位置跳变，形成摩尔纹。增加分辨率、降低频率、使用导数宽度（WebGL2/fwidth）或后处理模糊，都是缓解方式。

这也是为什么很多 shader 作品在 1080p 好看，在 4K 或小窗口却出现纹理噪点。

04自测

fract(uv) 和 floor(uv) 分别给你什么信息？

fract 给格子内的局部坐标（0..1）；floor 给格子的整数索引，用来判断第几个格子、奇偶等。

为什么棋盘用 mod(floor(x)+floor(y),2)？

相邻格子的行列索引之和奇偶交替，取模 2 就得到 0/1 的棋盘模式。

图案放大后出现摩尔纹，最直接的缓解方式？

降低图案频率或增加线宽/模糊；WebGL2 可以用 fwidth 根据屏幕导数自适应线宽。

这一讲带走

程序化图案的通用套路：放大 UV → fract 折叠 → floor 取索引 → step/smoothstep 画边界。掌握这套组合，条纹、点阵、瓷砖都能推出来。
