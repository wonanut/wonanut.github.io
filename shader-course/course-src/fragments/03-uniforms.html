01时间从哪来

WebGL 没有内置「时间」。你在 JS 里用 performance.now() 或 requestAnimationFrame 的时间戳，换算成秒，传给 shader 的 uTime。每一帧更新一次 uniform，画面就动了。

function frame(now) {
  const t = now * 0.001;              // 毫秒 → 秒
  gl.uniform1f(uTime, t);
  gl.drawArrays(gl.TRIANGLES, 0, 3);
  requestAnimationFrame(frame);
}
requestAnimationFrame(frame);

注意不要用 Date.now() 做动画时间，它会受系统时钟调整影响；performance.now() 单调递增，更适合动画。

02用周期函数构造动画

下面把屏幕坐标变成极坐标，用 sin(radius - time) 做出一圈圈向外扩散的环。整个过程没有 if，也没有状态，只有函数。

precision highp float;
varying vec2 vUv;
uniform vec2 uRes;
uniform float uTime;

void main() {
  vec2 p = vUv * 2.0 - 1.0;
  p.x *= uRes.x / uRes.y;
  float r = length(p);
  float ring = pow(0.5 + 0.5 * sin(r * 12.0 - uTime * 2.2), 8.0);
  vec3 col = mix(vec3(0.01,0.03,0.08),
                 vec3(0.1,0.7,0.65),
                 ring * smoothstep(1.4, 0.0, r));
  gl_FragColor = vec4(col, 1.0);
}
像水面上一圈圈扩散的波纹

时间每增加一点，波纹的相位就往前推一点；sin 负责形状，pow 负责让波峰变窄，smoothstep 负责让远处淡出。

类比到哪为止：水波是物理传播；这里的「波纹」只是数学函数，移动速度和间距都可以随手改。

03时间精度与帧率

动画速度应该按秒计算，而不是按帧。如果用 frameCount * 0.01，在 120Hz 屏幕上会比 60Hz 快一倍。用真实秒数就不会有这个问题。

长时间运行后 uTime 会变大

float 精度有限，运行几小时后时间的细粒度会变粗。长时间展示的 shader 可以把时间对某个周期取模，例如 uTime = t % 3600.0。

🔬 深入：为什么 shader 里很少写 if 来控制动画？

GPU 是 SIMD 执行，分支会让同一组线程走不同路径，降低效率；而且 if 写出来的动画容易不平滑。用 sin、smoothstep、mix 这类连续函数，既能得到平滑过渡，也更容易并行。

当然，判断命中、循环终止这类逻辑仍然需要 if/for；只是「形状与动画」尽量用数学函数表达。

05自测

为什么动画时间要用 performance.now() 而不是 Date.now()？

performance.now() 单调递增，不受系统时间调整影响；Date.now() 可能因为校时/时区变化跳变，导致动画跳帧。

sin 的函数值范围是多少？怎样映射到 0..1？

sin 返回 -1..1；用 0.5 + 0.5 * sin(x) 映射到 0..1。

为什么用 pow 处理 sin 的环？

pow 会压窄波峰、拉宽波谷，让环看起来更锐利、更像发光线条，而不是一大片渐变。
