01先建立最小心智模型

屏幕上的每个像素，最终都由 GPU 里的一小段程序决定颜色。WebGL 把这套过程拆成两个可编程阶段：顶点着色器决定几何体的顶点落在哪里；片元着色器决定每个像素最终是什么颜色。

本课程大部分 Demo 都是「全屏三角形 + 片元着色器」：屏幕上每个像素都会执行一次你写的 main()。你只要根据坐标算出颜色，就能画出无限复杂的图案。

像给每个像素发一张答题卡

片元着色器就是一张「你负责的像素」答题卡：卡上印着坐标、时间、鼠标等已知条件，你按要求填一个颜色交回去。GPU 会同时发出几百万张卡，所以每个 main() 都必须很轻。

类比到哪为止：答题卡之间不能互相通信；片元着色器无法读取邻居像素的颜色，这是它快的原因，也是很多效果要另想办法的原因。

先看一个最小片元 shader 的形状：它拿到当前像素的坐标，算出一个颜色，写进 gl_FragColor。

precision highp float;
uniform vec2 uRes;

void main() {
  vec2 uv = gl_FragCoord.xy / uRes;   // 0..1
  gl_FragColor = vec4(uv.x, uv.y, 0.5, 1.0);
}

这一小段会在屏幕每个像素上执行一次。把 uv.x 和 uv.y 分别送进红色和绿色通道，就得到一张从黑到黄、再到青的渐变图。整门课都是在这个形状上不断加东西。

🔬 深入：WebGL 1 和 WebGL 2 的 GLSL 有什么差别？

WebGL 1 使用 GLSL ES 1.00：没有 in/out，用 attribute、varying、gl_FragColor；不支持动态循环和纹理数组。WebGL 2 对应 GLSL ES 3.00，语法更现代，但入门阶段两者概念完全一致。

本课程使用 WebGL 1 语法，兼容面最广；你之后迁到 Three.js 的 ShaderMaterial 或 WebGL2 时，只需替换少量关键字。

05自测

片元着色器每个像素执行一次，那它能读取相邻像素的颜色吗？

不能。片元着色器只拿到当前片元的坐标和 uniform，无法访问邻居像素。需要邻域信息的效果通常要额外 pass、纹理或后处理。

为什么很多全屏 shader 用一个三角形，而不是两个三角形拼成矩形？

一个覆盖屏幕的大三角形少一个顶点、少一条对角线，光栅化更简单；对全屏后处理来说足够，且能减少边界处的重复计算。

顶点着色器和片元着色器，哪个决定「像素颜色」？

片元着色器。顶点着色器只决定顶点位置与传给片元的 varying；颜色最终在片元阶段计算并写入帧缓冲。
