01为什么需要 shader

在 GPU 还能被编程之前，图形管线是「固定功能」的：你只能设置光源、材质、雾等参数，具体怎么算由厂商写死。想让一个物体表面出现卡通色阶、水面折射或自定义噪声，只能等新硬件或新 API。

可编程 shader 出现后，开发者可以接管两个关键阶段：顶点怎么变换、像素怎么上色。今天你在网页上看到的渐变按钮、粒子背景、产品 3D 展示、数据可视化、视频游戏、甚至「3 渲 2」的动画风格，背后都可能是同一套 shader 思路。

真实案例 · 它不只是特效

电商首页的光晕背景、音乐 App 的频谱、地图的流场、游戏里的角色描边、产品页的可旋转 3D 模型——这些效果的共同点是：需要逐像素/逐顶点的自定义计算，而不是简单贴一张图。

所以学 shader 的收益不是「会写一个酷炫背景」，而是获得一种能力：用数学直接描述画面。这也意味着它比写普通业务代码更依赖直觉和实验。

02CPU 与 GPU：两种完全不同的快

CPU 像几个很聪明的专家，擅长复杂分支、缓存、串行逻辑；GPU 像几千个流水线工人，每个人只会做简单计算，但同时开工。片元着色器就是「每个像素一个工人」：同一段代码在几百万个像素上并行执行。

维度CPUGPU
核心数量少（几到几十）多（成百上千）
擅长复杂逻辑、分支、调度大量相同、简单的计算
shader 里的含义准备数据、发 draw call并行处理顶点与像素
最怕频繁同步、过度抽象分支发散、纹理采样过多

这也解释了一个常见误区：shader 里的 `if` 不是不能用，而是「同一组线程走不同分支」会降低效率。初学阶段可以先写清楚，再逐步把形状和动画改写成连续函数。

03WebGL 是什么，不是什么

WebGL 是浏览器里的底层图形 API，大致对应 OpenGL ES 2.0（WebGL 1）与 ES 3.0（WebGL 2）。它只负责「把顶点和片元程序交给 GPU」这件事，不提供场景图、相机、模型加载、光照系统。

Three.js、Babylon.js、PlayCanvas 这些库都建立在 WebGL 之上；它们帮你管理场景和材质，但最终仍然要编译 GLSL、发 draw call。学会原生 WebGL，再换框架就只是换 API。

先修要求

会 JavaScript、知道什么是 canvas 就够。不需要线性代数基础：本课只用到向量加减、点积、`mix`、`sin`、`fract` 这些工具，遇到时会现场解释。

04数学热身：四个够用的工具

工具直觉在 shader 里做什么
向量 vec2/vec3带方向/分量的数坐标、颜色、法线
dot(a,b)两个方向的接近程度光照、边缘、投影
mix(a,b,t)按比例混合渐变、颜色过渡
smoothstep(e0,e1,x)柔和地判断「在不在范围内」遮罩、柔边、抗锯齿

不要被「数学」吓到。shader 的美妙之处是：你能立刻看到公式长什么样。把 `sin` 的频率改一倍，画面就会给你反馈；这种即时反馈比推导公式更适合入门。

06先建立最小心智模型

屏幕上的每个像素，最终都由 GPU 里的一小段程序决定颜色。WebGL 把这套过程拆成两个可编程阶段：顶点着色器决定几何体的顶点落在哪里；片元着色器决定每个像素最终是什么颜色。

本课程大部分 Demo 都是「全屏三角形 + 片元着色器」：屏幕上每个像素都会执行一次你写的 main()。你只要根据坐标算出颜色，就能画出无限复杂的图案。

JS准备数据与 uniform
→
Vertex顶点位置 / 插值
→
Rasterizer变成像素
→
Fragment每个像素算颜色
像给每个像素发一张答题卡

片元着色器就是一张「你负责的像素」答题卡：卡上印着坐标、时间、鼠标等已知条件，你按要求填一个颜色交回去。GPU 会同时发出几百万张卡，所以每个 main() 都必须很轻。

类比到哪为止：答题卡之间不能互相通信；片元着色器无法读取邻居像素的颜色，这是它快的原因，也是很多效果要另想办法的原因。

先看一个最小片元 shader 的形状：它拿到当前像素的坐标，算出一个颜色，写进 gl_FragColor。

precision highp float;
uniform vec2 uRes;

void main() {
  vec2 uv = gl_FragCoord.xy / uRes;   // 0..1
  gl_FragColor = vec4(uv.x, uv.y, 0.5, 1.0);
}

这一小段会在屏幕每个像素上执行一次。把 uv.x 和 uv.y 分别送进红色和绿色通道，就得到一张从黑到黄、再到青的渐变图。整门课都是在这个形状上不断加东西。

🔬 深入：WebGL 1 和 WebGL 2 的 GLSL 有什么差别？

WebGL 1 使用 GLSL ES 1.00：没有 in/out，用 attribute、varying、gl_FragColor；不支持动态循环和纹理数组。WebGL 2 对应 GLSL ES 3.00，语法更现代，但入门阶段两者概念完全一致。

本课程使用 WebGL 1 语法，兼容面最广；你之后迁到 Three.js 的 ShaderMaterial 或 WebGL2 时，只需替换少量关键字。

09卡住时，先检查这四件事

黑屏排查顺序

① canvas 的 CSS 宽高是否为 0；② shader 是否编译成功（看控制台报错）；③ attribute/uniform 名字是否拼错、是否被优化掉；④ 是否忘了设置 viewport 或清屏。大多数「没有画面」都不是数学错，而是状态没设对。

建议每写一个新 shader，先输出一个纯色，确认管线通了，再逐步加 UV、时间、图案。把「能显示」和「显示得对」分开调试，比一次性写完再猜快得多。

11自测

片元着色器每个像素执行一次，那它能读取相邻像素的颜色吗？

不能。片元着色器只拿到当前片元的坐标和 uniform，无法访问邻居像素。需要邻域信息的效果通常要额外 pass、纹理或后处理。

为什么很多全屏 shader 用一个三角形，而不是两个三角形拼成矩形？

一个覆盖屏幕的大三角形少一个顶点、少一条对角线，光栅化更简单；对全屏后处理来说足够，且能减少边界处的重复计算。

顶点着色器和片元着色器，哪个决定「像素颜色」？

片元着色器。顶点着色器只决定顶点位置与传给片元的 varying；颜色最终在片元阶段计算并写入帧缓冲。
