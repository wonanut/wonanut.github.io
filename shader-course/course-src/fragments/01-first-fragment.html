01先把坐标理清

顶点着色器输出的位置在 clip space：x、y 都在 -1 到 1 之间，(-1,-1) 是左下，(+1,+1) 是右上。光栅化之后，片元着色器拿到的是像素坐标，通常用 gl_FragCoord.xy，范围是画布宽高。

最常用的中间量是 UV：把坐标归一化到 0..1。归一化后，图案不依赖画布具体像素尺寸，换屏幕也能保持比例。但注意：直接把 gl_FragCoord.xy / uRes 当 UV，会让圆变成椭圆，因为屏幕通常不是正方形；需要乘宽高比。

像给每个像素发一张带经纬度的答题卡

UV 就是像素的经纬度，告诉你「你在画面的哪个位置」。颜色函数则是答题规则：给定经纬度，返回一个颜色。

类比到哪为止：真实地图的经纬度是连续的；shader 里的 UV 每个像素只采样一次，所以高频图案会出现锯齿，这也是后面要学抗锯齿的原因。

02全屏三角形

为了覆盖整个画布，我们只画一个三角形：三个顶点放在裁剪空间外，确保它盖住屏幕。片元阶段再根据 UV 上色。这个技巧比画两个三角形组成矩形更省一点，也避免对角线接缝。

const positions = new Float32Array([
  -1, -1,
   3, -1,
  -1,  3,
]);

gl.bindBuffer(gl.ARRAY_BUFFER, buffer);
gl.bufferData(gl.ARRAY_BUFFER, positions, gl.STATIC_DRAW);
gl.drawArrays(gl.TRIANGLES, 0, 3);

03第一个片元 shader

顶点着色器只做一件事：把顶点坐标传给光栅化，并顺便算好 UV。片元着色器则拿 UV 算颜色：

precision highp float;
varying vec2 vUv;
uniform vec2 uRes;
uniform vec2 uMouse;

void main() {
  vec3 col = mix(vec3(0.02,0.03,0.08),
                 vec3(0.08,0.55,0.62),
                 vUv.y);
  float d = distance(vUv * vec2(uRes.x/uRes.y, 1.0),
                     uMouse * vec2(uRes.x/uRes.y, 1.0));
  col += vec3(0.3,0.9,0.85) * smoothstep(0.4, 0.0, d) * 0.6;
  gl_FragColor = vec4(col, 1.0);
}

mix(a,b,t) 做线性插值，smoothstep 做柔和的 0→1 过渡。用 smoothstep 而不是 step，光斑边缘会柔和很多。

宽高比是 shader 里最常见的坑

把 x 乘上 uRes.x / uRes.y，能让「以中心为圆心的距离」在屏幕坐标里保持圆形。否则在 16:9 屏幕上，圆会横向拉长。

🔬 深入：为什么 Demo 的鼠标高光不是简单的圆？

它其实叠加了两个形状：一个柔和的圆形高光，和一个以 (0.5,0.8) 为圆心的细环。每个形状都用 smoothstep 控制衰减，最后相加。你看到的「发光」不是物理光，而是颜色叠加。

很多看起来复杂的 shader 都是这样：几个简单的距离/噪声函数相加或相乘。先学会读每一项，再谈组合。

04动手实验

  1. 把 vUv.y 换成 vUv.x，观察渐变方向；再把 mix 的两种颜色对调。
  2. 把 smoothstep(0.4, 0.0, d) 改成 smoothstep(0.2, 0.0, d) * 2.0，让光斑更小更亮。

05自测

为什么 UV 要乘宽高比？

因为画布像素不是正方形。要让距离函数在屏幕空间保持各向同性，需要把 x 乘以 width / height，否则圆会被拉成椭圆。

mix(a,b,0.3) 的结果是什么？

返回 a * 0.7 + b * 0.3 的线性插值。t 可以大于 1 或小于 0，但通常我们保持在 0..1。

全屏三角形为什么顶点会超出 [-1,1]？

超出的部分会被裁剪，但留下的区域正好覆盖整个视口；这样只用三个顶点就盖满屏幕，避免两个三角形拼矩形的对角线接缝。

这一讲带走

坐标的层级是：clip space → 屏幕像素 → UV。记住乘宽高比、用 smoothstep 做柔边，你就已经能画出一张像样的全屏图。
