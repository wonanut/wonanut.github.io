01管线里的三种变量

变量声明在从哪里来典型用途
attribute顶点着色器JavaScript 的顶点缓冲位置、法线、颜色
uniform两个着色器JavaScript 每次绘制传入时间、分辨率、矩阵
varying两个着色器顶点着色器输出 → 光栅化插值UV、顶点颜色、法线

顶点着色器每个顶点执行一次；片元着色器每个像素执行一次。三个顶点的颜色之所以能变成一整片渐变，是因为光栅化阶段会把 varying 按重心坐标插值。

像把三盏灯的亮度摊到整个房间

三个顶点是三盏颜色不同的灯，片元是房间里的每个点。光栅化会根据你离三盏灯的距离做加权平均，于是每个像素得到一个混合色。

类比到哪为止：插值是线性的，所以颜色从顶点到顶点是平滑过渡；如果三个顶点颜色相同，整个三角形就是纯色。

02顶点着色器

这段 shader 接收位置和颜色两个 attribute，用旋转矩阵转动位置，再把颜色作为 varying 传给片元。gl_Position 是必须写入的裁剪空间坐标。

attribute vec2 aPos;
attribute vec3 aColor;
uniform float uTime;
varying vec3 vColor;

void main() {
  float a = uTime * 0.5;
  mat2 r = mat2(cos(a), -sin(a), sin(a), cos(a));
  vec2 p = r * aPos;
  gl_Position = vec4(p, 0.0, 1.0);
  vColor = aColor;
}

03片元着色器与 draw call

片元着色器只接收插值后的 vColor，做一点呼吸亮度后输出。注意它完全不知道三角形有几个顶点，也不知道顶点颜色来自哪里。

precision highp float;
varying vec3 vColor;
uniform float uTime;

void main() {
  float pulse = 0.85 + 0.15 * sin(uTime * 2.0);
  gl_FragColor = vec4(vColor * pulse, 1.0);
}

JavaScript 侧只需要把两个 buffer 绑到 attribute 位置，然后 drawArrays(TRIANGLES, 0, 3)。颜色数组长度是 9，因为 3 个顶点 × RGB 3 个分量。

🔬 深入：为什么 varying 不能随便传大数组？

varying 的数量受 GPU 限制，而且每个顶点都要写入、每个片元都要读取。传纹理坐标和法线通常够用；如果需要大量每顶点数据，应该用纹理或实例化属性，而不是堆几十个 varying。

另一个限制是精度：WebGL 1 的 varying 默认可能是 mediump，移动端尤其要小心位置/UV 的精度。

04自测

三个顶点分别是红、绿、蓝，三角形中心大概是什么颜色？

三者的加权平均，接近灰/白。正中心重心坐标约为 (1/3,1/3,1/3)，所以 RGB 各约 0.33。

uniform 和 attribute 的最大区别？

attribute 是逐顶点数据，来自顶点缓冲；uniform 是一次 draw call 内所有顶点/片元共享的常量，由 JS 在绘制前设置。

为什么片元着色器不直接接收顶点数组？

片元阶段处理的是光栅化后的像素，不持有顶点数组；它只能拿到插值后的 varying 和 uniform。这样 GPU 才能并行处理大量像素。

这一讲带走

顶点着色器决定「顶点在哪、传什么 varying」，光栅化负责插值，片元着色器只负责「当前像素是什么颜色」。这就是几何体上色的全部秘密。
