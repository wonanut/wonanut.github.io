01为什么需要 shader

在 GPU 还能被编程之前，图形管线是「固定功能」的：你只能设置光源、材质、雾等参数，具体怎么算由厂商写死。想让一个物体表面出现卡通色阶、水面折射或自定义噪声，只能等新硬件或新 API。

可编程 shader 出现后，开发者可以接管两个关键阶段：顶点怎么变换、像素怎么上色。今天你在网页上看到的渐变按钮、粒子背景、产品 3D 展示、数据可视化、视频游戏、甚至「3 渲 2」的动画风格，背后都可能是同一套 shader 思路。

真实案例 · 它不只是特效

电商首页的光晕背景、音乐 App 的频谱、地图的流场、游戏里的角色描边、产品页的可旋转 3D 模型——这些效果的共同点是：需要逐像素/逐顶点的自定义计算，而不是简单贴一张图。

所以学 shader 的收益不是「会写一个酷炫背景」，而是获得一种能力：用数学直接描述画面。这也意味着它比写普通业务代码更依赖直觉和实验。

02CPU 与 GPU：两种完全不同的快

CPU 像几个很聪明的专家，擅长复杂分支、缓存、串行逻辑；GPU 像几千个流水线工人，每个人只会做简单计算，但同时开工。片元着色器就是「每个像素一个工人」：同一段代码在几百万个像素上并行执行。

维度CPUGPU
核心数量少（几到几十）多（成百上千）
擅长复杂逻辑、分支、调度大量相同、简单的计算
shader 里的含义准备数据、发 draw call并行处理顶点与像素
最怕频繁同步、过度抽象分支发散、纹理采样过多

这也解释了一个常见误区：shader 里的 `if` 不是不能用，而是「同一组线程走不同分支」会降低效率。初学阶段可以先写清楚，再逐步把形状和动画改写成连续函数。

03WebGL 是什么，不是什么

WebGL 是浏览器里的底层图形 API，大致对应 OpenGL ES 2.0（WebGL 1）与 ES 3.0（WebGL 2）。它只负责「把顶点和片元程序交给 GPU」这件事，不提供场景图、相机、模型加载、光照系统。

Three.js、Babylon.js、PlayCanvas 这些库都建立在 WebGL 之上；它们帮你管理场景和材质，但最终仍然要编译 GLSL、发 draw call。学会原生 WebGL，再换框架就只是换 API。

先修要求

会 JavaScript、知道什么是 canvas 就够。不需要线性代数基础：本课只用到向量加减、点积、`mix`、`sin`、`fract` 这些工具，遇到时会现场解释。

06先建立最小心智模型

屏幕上的每个像素，最终都由 GPU 里的一小段程序决定颜色。WebGL 把这套过程拆成两个可编程阶段：顶点着色器决定几何体的顶点落在哪里；片元着色器决定每个像素最终是什么颜色。

本课程大部分 Demo 都是「全屏三角形 + 片元着色器」：屏幕上每个像素都会执行一次你写的 main()。你只要根据坐标算出颜色，就能画出无限复杂的图案。

像给每个像素发一张答题卡

片元着色器就是一张「你负责的像素」答题卡：卡上印着坐标、时间、鼠标等已知条件，你按要求填一个颜色交回去。GPU 会同时发出几百万张卡，所以每个 main() 都必须很轻。

类比到哪为止：答题卡之间不能互相通信；片元着色器无法读取邻居像素的颜色，这是它快的原因，也是很多效果要另想办法的原因。

先看一个最小片元 shader 的形状：它拿到当前像素的坐标，算出一个颜色，写进 gl_FragColor。

precision highp float;
uniform vec2 uRes;

void main() {
  vec2 uv = gl_FragCoord.xy / uRes;   // 0..1
  gl_FragColor = vec4(uv.x, uv.y, 0.5, 1.0);
}

这一小段会在屏幕每个像素上执行一次。把 uv.x 和 uv.y 分别送进红色和绿色通道，就得到一张从黑到黄、再到青的渐变图。整门课都是在这个形状上不断加东西。

🔬 深入：WebGL 1 和 WebGL 2 的 GLSL 有什么差别？

11自测

片元着色器每个像素执行一次，那它能读取相邻像素的颜色吗？

不能。片元着色器只拿到当前片元的坐标和 uniform，无法访问邻居像素。需要邻域信息的效果通常要额外 pass、纹理或后处理。

为什么很多全屏 shader 用一个三角形，而不是两个三角形拼成矩形？

一个覆盖屏幕的大三角形少一个顶点、少一条对角线，光栅化更简单；对全屏后处理来说足够，且能减少边界处的重复计算。

顶点着色器和片元着色器，哪个决定「像素颜色」？

片元着色器。顶点着色器只决定顶点位置与传给片元的 varying；颜色最终在片元阶段计算并写入帧缓冲。

01先把坐标理清

顶点着色器输出的位置在 clip space：x、y 都在 -1 到 1 之间，(-1,-1) 是左下，(+1,+1) 是右上。光栅化之后，片元着色器拿到的是像素坐标，通常用 gl_FragCoord.xy，范围是画布宽高。

最常用的中间量是 UV：把坐标归一化到 0..1。归一化后，图案不依赖画布具体像素尺寸，换屏幕也能保持比例。但注意：直接把 gl_FragCoord.xy / uRes 当 UV，会让圆变成椭圆，因为屏幕通常不是正方形；需要乘宽高比。

像给每个像素发一张带经纬度的答题卡

UV 就是像素的经纬度，告诉你「你在画面的哪个位置」。颜色函数则是答题规则：给定经纬度，返回一个颜色。

类比到哪为止：真实地图的经纬度是连续的；shader 里的 UV 每个像素只采样一次，所以高频图案会出现锯齿，这也是后面要学抗锯齿的原因。

02全屏三角形

为了覆盖整个画布，我们只画一个三角形：三个顶点放在裁剪空间外，确保它盖住屏幕。片元阶段再根据 UV 上色。这个技巧比画两个三角形组成矩形更省一点，也避免对角线接缝。

gl.drawArrays(gl.TRIANGLES, 0, 3);

03第一个片元 shader

顶点着色器只做一件事：把顶点坐标传给光栅化，并顺便算好 UV。片元着色器则拿 UV 算颜色：

precision highp float;
varying vec2 vUv;
uniform vec2 uRes;
uniform vec2 uMouse;

void main() {
  vec3 col = mix(vec3(0.02,0.03,0.08),
                 vec3(0.08,0.55,0.62),
                 vUv.y);
  float d = distance(vUv * vec2(uRes.x/uRes.y, 1.0),
                     uMouse * vec2(uRes.x/uRes.y, 1.0));
  col += vec3(0.3,0.9,0.85) * smoothstep(0.4, 0.0, d) * 0.6;
  gl_FragColor = vec4(col, 1.0);
}

mix(a,b,t) 做线性插值，smoothstep 做柔和的 0→1 过渡。用 smoothstep 而不是 step，光斑边缘会柔和很多。

宽高比是 shader 里最常见的坑

把 x 乘上 uRes.x / uRes.y，能让「以中心为圆心的距离」在屏幕坐标里保持圆形。否则在 16:9 屏幕上，圆会横向拉长。

🔬 深入：为什么 Demo 的鼠标高光不是简单的圆？

它其实叠加了两个形状：一个柔和的圆形高光，和一个以 (0.5,0.8) 为圆心的细环。每个形状都用 smoothstep 控制衰减，最后相加。你看到的「发光」不是物理光，而是颜色叠加。

很多看起来复杂的 shader 都是这样：几个简单的距离/噪声函数相加或相乘。先学会读每一项，再谈组合。

05自测

为什么 UV 要乘宽高比？

因为画布像素不是正方形。要让距离函数在屏幕空间保持各向同性，需要把 x 乘以 width / height，否则圆会被拉成椭圆。

mix(a,b,0.3) 的结果是什么？

返回 a * 0.7 + b * 0.3 的线性插值。t 可以大于 1 或小于 0，但通常我们保持在 0..1。

全屏三角形为什么顶点会超出 [-1,1]？

超出的部分会被裁剪，但留下的区域正好覆盖整个视口；这样只用三个顶点就盖满屏幕，避免两个三角形拼矩形的对角线接缝。

这一讲带走

坐标的层级是：clip space → 屏幕像素 → UV。记住乘宽高比、用 smoothstep 做柔边，你就已经能画出一张像样的全屏图。

01管线里的三种变量

变量声明在从哪里来典型用途
attribute顶点着色器JavaScript 的顶点缓冲位置、法线、颜色
uniform两个着色器JavaScript 每次绘制传入时间、分辨率、矩阵
varying两个着色器顶点着色器输出 → 光栅化插值UV、顶点颜色、法线

顶点着色器每个顶点执行一次；片元着色器每个像素执行一次。三个顶点的颜色之所以能变成一整片渐变，是因为光栅化阶段会把 varying 按重心坐标插值。

像把三盏灯的亮度摊到整个房间

三个顶点是三盏颜色不同的灯，片元是房间里的每个点。光栅化会根据你离三盏灯的距离做加权平均，于是每个像素得到一个混合色。

类比到哪为止：插值是线性的，所以颜色从顶点到顶点是平滑过渡；如果三个顶点颜色相同，整个三角形就是纯色。

02顶点着色器

这段 shader 接收位置和颜色两个 attribute，用旋转矩阵转动位置，再把颜色作为 varying 传给片元。gl_Position 是必须写入的裁剪空间坐标。

attribute vec2 aPos;
attribute vec3 aColor;
uniform float uTime;
varying vec3 vColor;

void main() {
  float a = uTime * 0.5;
  mat2 r = mat2(cos(a), -sin(a), sin(a), cos(a));
  vec2 p = r * aPos;
  gl_Position = vec4(p, 0.0, 1.0);
  vColor = aColor;
}

03片元着色器与 draw call

片元着色器只接收插值后的 vColor，做一点呼吸亮度后输出。注意它完全不知道三角形有几个顶点，也不知道顶点颜色来自哪里。

precision highp float;
varying vec3 vColor;
uniform float uTime;

void main() {
  float pulse = 0.85 + 0.15 * sin(uTime * 2.0);
  gl_FragColor = vec4(vColor * pulse, 1.0);
}

JavaScript 侧只需要把两个 buffer 绑到 attribute 位置，然后 drawArrays(TRIANGLES, 0, 3)。颜色数组长度是 9，因为 3 个顶点 × RGB 3 个分量。

🔬 深入：为什么 varying 不能随便传大数组？

varying 的数量受 GPU 限制，而且每个顶点都要写入、每个片元都要读取。传纹理坐标和法线通常够用；如果需要大量每顶点数据，应该用纹理或实例化属性，而不是堆几十个 varying。

另一个限制是精度：WebGL 1 的 varying 默认可能是 mediump，移动端尤其要小心位置/UV 的精度。

案例 · 低多边形渐变与 UI 按钮

低多边形插值、渐变按钮、加载进度条，底层都是「顶点属性 + 插值」。颜色从顶点传到片元，是最轻量的渐变方案。

04自测

三个顶点分别是红、绿、蓝，三角形中心大概是什么颜色？

三者的加权平均，接近灰/白。正中心重心坐标约为 (1/3,1/3,1/3)，所以 RGB 各约 0.33。

uniform 和 attribute 的最大区别？

attribute 是逐顶点数据，来自顶点缓冲；uniform 是一次 draw call 内所有顶点/片元共享的常量，由 JS 在绘制前设置。

为什么片元着色器不直接接收顶点数组？

片元阶段处理的是光栅化后的像素，不持有顶点数组；它只能拿到插值后的 varying 和 uniform。这样 GPU 才能并行处理大量像素。

这一讲带走

顶点着色器决定「顶点在哪、传什么 varying」，光栅化负责插值，片元着色器只负责「当前像素是什么颜色」。这就是几何体上色的全部秘密。

第 3 讲 · 图形管线

uniform 与时间：让画面动起来同一个 shader，每帧只改一个 uTime，就能得到连续的动画

静态图案只是开始。shader 的动画不需要改顶点或重建几何体，只要把时间作为 uniform 传进去，让颜色/位置随时间变化。

Demo 3 · 时间脉冲 关键词 uniform float uTime · sin · fract

  • 学完这一讲，你会
  • 把 requestAnimationFrame 的时间传给 shader
  • 用 sin / fract 构造周期动画，而不是写 if-else
  • 避免时间精度与帧率带来的常见问题

01时间从哪来

WebGL 没有内置「时间」。你在 JS 里用 performance.now() 或 requestAnimationFrame 的时间戳，换算成秒，传给 shader 的 uTime。每一帧更新一次 uniform，画面就动了。

function frame(now) {
  const t = now * 0.001;              // 毫秒 → 秒
  gl.uniform1f(uTime, t);
  gl.drawArrays(gl.TRIANGLES, 0, 3);
  requestAnimationFrame(frame);
}
requestAnimationFrame(frame);

注意不要用 Date.now() 做动画时间，它会受系统时钟调整影响；performance.now() 单调递增，更适合动画。

02用周期函数构造动画

下面把屏幕坐标变成极坐标，用 sin(radius - time) 做出一圈圈向外扩散的环。整个过程没有 if，也没有状态，只有函数。

precision highp float;
varying vec2 vUv;
uniform vec2 uRes;
uniform float uTime;

void main() {
  vec2 p = vUv * 2.0 - 1.0;
  p.x *= uRes.x / uRes.y;
  float r = length(p);
  float ring = pow(0.5 + 0.5 * sin(r * 12.0 - uTime * 2.2), 8.0);
  vec3 col = mix(vec3(0.01,0.03,0.08),
                 vec3(0.1,0.7,0.65),
                 ring * smoothstep(1.4, 0.0, r));
  gl_FragColor = vec4(col, 1.0);
}
像水面上一圈圈扩散的波纹

时间每增加一点，波纹的相位就往前推一点；sin 负责形状，pow 负责让波峰变窄，smoothstep 负责让远处淡出。

类比到哪为止：水波是物理传播；这里的「波纹」只是数学函数，移动速度和间距都可以随手改。

03时间精度与帧率

动画速度应该按秒计算，而不是按帧。如果用 frameCount * 0.01，在 120Hz 屏幕上会比 60Hz 快一倍。用真实秒数就不会有这个问题。

长时间运行后 uTime 会变大

float 精度有限，运行几小时后时间的细粒度会变粗。长时间展示的 shader 可以把时间对某个周期取模，例如 uTime = t % 3600.0。

🔬 深入：为什么 shader 里很少写 if 来控制动画？

GPU 是 SIMD 执行，分支会让同一组线程走不同路径，降低效率；而且 if 写出来的动画容易不平滑。用 sin、smoothstep、mix 这类连续函数，既能得到平滑过渡，也更容易并行。

当然，判断命中、循环终止这类逻辑仍然需要 if/for；只是「形状与动画」尽量用数学函数表达。

04动手实验

  1. 把 uTime * 2.2 改成 uTime * 0.8，观察波纹扩散速度。
  2. 把 pow(..., 8.0) 改成 4.0 或 16.0，看波峰宽度如何变化。

加载页面的扩散圆环、音频可视化的柱状条，都可以用时间 uniform 驱动 sin/abs 函数得到。

05自测

为什么动画时间要用 performance.now() 而不是 Date.now()？

performance.now() 单调递增，不受系统时间调整影响；Date.now() 可能因为校时/时区变化跳变，导致动画跳帧。

sin 的函数值范围是多少？怎样映射到 0..1？

sin 返回 -1..1；用 0.5 + 0.5 * sin(x) 映射到 0..1。

为什么用 pow 处理 sin 的环？

pow 会压窄波峰、拉宽波谷，让环看起来更锐利、更像发光线条，而不是一大片渐变。

第 4 讲 · 图形管线

UV 图案：step、fract 与棋盘把连续坐标切成格子，是所有程序化图案的起点

棋盘、条纹、点阵、网格——看起来不同的图案，底层都是同一组操作：放大 UV、取小数部分、判断奇偶、用 smoothstep 画线。

Demo 4 · 程序化棋盘 关键词 fract · step · mod

  • 学完这一讲，你会
  • 用 fract 把坐标折叠成重复格子
  • 用 floor/mod 判断奇偶格，用 smoothstep 画网格线
  • 理解放大 UV 与抗锯齿之间的关系

01把空间切成格子

核心操作只有两个：uv *= n 放大坐标，fract(uv) 取小数部分。放大后每个整数区间变成一个格子，fract 把它们折叠回 0..1。floor(uv) 则告诉你当前在第几个格子。

vec2 uv = vUv * vec2(uRes.x/uRes.y, 1.0) * 8.0;
vec2 g = abs(fract(uv) - 0.5);             // 到格子中心的距离
float checker = mod(floor(uv.x) + floor(uv.y), 2.0);
float line = smoothstep(0.49, 0.5, max(g.x, g.y));

checker 为 0/1，用来选两种底色；line 在靠近格子边界时接近 1，用来画网格线。两者叠加就是一个会动起来的棋盘。

像地砖的铺法

放大 UV 相当于决定每块地砖多大；fract 是「你在这块砖里的哪个位置」；floor 是「你在第几行第几列」。改砖的大小、颜色和缝隙，就能得到完全不同的图案。

类比到哪为止：真实地砖有物理缝隙；shader 里的「缝隙」只是 smoothstep 画出来的一条颜色带。

02完整片段

precision highp float;
varying vec2 vUv;
uniform vec2 uRes;
uniform float uTime;

void main() {
  vec2 uv = vUv * vec2(uRes.x/uRes.y, 1.0) * 8.0;
  uv += vec2(uTime * 0.08, sin(uTime * 0.3));
  vec2 g = abs(fract(uv) - 0.5);
  float checker = mod(floor(uv.x) + floor(uv.y), 2.0);
  float line = smoothstep(0.49, 0.5, max(g.x, g.y));
  vec3 col = mix(vec3(0.02,0.04,0.08),
                 vec3(0.08,0.5,0.55),
                 checker * 0.35 + 0.1);
  col = mix(col, vec3(0.75,0.9,0.95), line * 0.65);
  gl_FragColor = vec4(col, 1.0);
}

03抗锯齿

当格子很密时，一条像素可能跨过多个格子，硬边会出现摩尔纹和闪烁。WebGL 1 没有内置 fwidth，但可以用两个 smoothstep 控制线宽，或降低图案频率、加一点模糊。先把图案做「粗」一点，通常比事后抗锯齿更有效。

🔬 深入：为什么放大 UV 会让边缘闪烁？

因为像素是离散采样。当图案频率接近像素频率时，采样结果会在不同帧/不同位置跳变，形成摩尔纹。增加分辨率、降低频率、使用导数宽度（WebGL2/fwidth）或后处理模糊，都是缓解方式。

这也是为什么很多 shader 作品在 1080p 好看，在 4K 或小窗口却出现纹理噪点。

案例 · 赛博扫描线与游戏地图

扫描线、网格地面、雷达 UI 都依赖 fract/step；把 UV 放大到合适频率，是控制「格子密度」的关键。

04自测

fract(uv) 和 floor(uv) 分别给你什么信息？

fract 给格子内的局部坐标（0..1）；floor 给格子的整数索引，用来判断第几个格子、奇偶等。

为什么棋盘用 mod(floor(x)+floor(y),2)？

相邻格子的行列索引之和奇偶交替，取模 2 就得到 0/1 的棋盘模式。

图案放大后出现摩尔纹，最直接的缓解方式？

降低图案频率或增加线宽/模糊；WebGL2 可以用 fwidth 根据屏幕导数自适应线宽。

程序化图案的通用套路：放大 UV → fract 折叠 → floor 取索引 → step/smoothstep 画边界。掌握这套组合，条纹、点阵、瓷砖都能推出来。

第 5 讲 · 程序化图形

噪声与 FBM：程序化云层hash 生成随机，value noise 做平滑，FBM 把多层细节叠起来

规则图案看多了会腻。自然界的云、雾、岩石都有「随机但有结构」的纹理，噪声函数就是 shader 里生成这种纹理的万能工具。

Demo 5 · FBM 云层 关键词 hash · value noise · fbm

  • 学完这一讲，你会
  • 用 hash 把坐标映射成伪随机值
  • 用双线性插值把随机点变成平滑噪声
  • 用 FBM 叠加多个八度，得到云层一样的细节

01从 hash 开始

真正的随机数在 shader 里成本高且不可复现；我们只需要「同样的坐标永远得到同样的随机值」。一个常见的 hash 是把坐标做 sin/点乘/fract 组合：

float hash(vec2 p) {
  p = fract(p * vec2(123.34, 345.45));
  p += dot(p, p + 34.345);
  return fract(p.x * p.y);
}

hash 输出的值在格子之间是跳变的，直接用会像电视雪花。下一步是在格子之间做平滑插值，这就是 value noise。

02value noise 与 FBM

在整数格点上取 hash，再对四个角做 smoothstep 插值。单层噪声已经有点云的感觉，但缺少细节；FBM 把噪声按频率翻倍、振幅减半地叠加：

float noise(vec2 p) {
  vec2 i = floor(p), f = fract(p);
  f = f * f * (3.0 - 2.0 * f);
  float a = hash(i);
  float b = hash(i + vec2(1.0, 0.0));
  float c = hash(i + vec2(0.0, 1.0));
  float d = hash(i + vec2(1.0, 1.0));
  return mix(mix(a, b, f.x), mix(c, d, f.x), f.y);
}

float fbm(vec2 p) {
  float v = 0.0, a = 0.5;
  for (int i = 0; i < 5; i++) {
    v += a * noise(p);
    p *= 2.03;
    a *= 0.5;
  }
  return v;
}
像用不同粗细的笔刷叠画

第一层是大笔刷，决定云的大块形状；第二层细一点，补边缘；第三层更细，补毛刺。振幅逐层减半，避免细节盖过整体。

类比到哪为止：画画可以随时收笔；shader 里的层数是固定的，层数越多越贵，需要按性能取舍。

03上色

把 fbm 的输出当作密度：低密度给深色，高密度给亮色，再用 smoothstep 做柔和过渡。颜色不要直接用 RGB 随机，而是取一个有限色板，画面会更统一。

float f = fbm(vUv * 3.2 + vec2(uTime * 0.03, uTime * 0.02));
vec3 col = mix(vec3(0.02,0.03,0.08),
               vec3(0.12,0.55,0.60),
               smoothstep(0.35, 0.7, f));
col += vec3(0.7,0.3,0.8) * smoothstep(0.55, 0.82, f) * 0.45;
🔬 深入：value noise 和 simplex noise 差在哪？

value noise 在格点上取随机值再插值，计算便宜，但容易看出网格方向；simplex/perlin noise 在梯度上插值，方向性更弱、观感更自然，但实现更复杂。FBM 对两者都适用。

移动端预算紧时，value noise 往往是更实际的选择；需要更「有机」的形状时，再换 simplex。

案例 · 云、火、水面

FBM 是云层与地形的基础；火焰通常再叠一个向上的 UV 偏移，水面则把噪声当作法线扰动。

04自测

hash 的作用是什么？

把坐标映射成固定但看起来随机的值；同样的输入永远得到同样的输出，所以动画可复现、无需存储随机表。

为什么 FBM 每层要乘 2.03 而不是 2.0？

避免频率正好成整数倍导致重复图案；稍微错开可以掩盖周期性。振幅同时减半，保证细节不会压过整体。

FBM 层数越多，画面越好吗？

不一定。层数增加提升细节，但也线性增加开销；很多场景 4–6 层已经足够，剩下的交给颜色和构图。

这一讲带走

hash 产生随机，noise 把随机变平滑，FBM 把平滑叠出细节。三者组合是云、雾、地形、水面等所有自然纹理的起点。

第 6 讲 · 程序化图形

SDF：用距离函数塑造形状不画三角形，也能算出圆的边界；smooth min 让形状自然融合

Signed Distance Field（有符号距离场）用一个函数告诉你「点到形状边界有多远」。正数在外部，负数在内部，零就是边界。它既能在 2D 做图形，也是 raymarching 的基础。

Demo 6 · 可交互的 metaball 关键词 sdf · smooth min · smoothstep

  • 学完这一讲，你会
  • 写出圆、矩形等基础 SDF，并用距离判断内外
  • 用 smooth min 把多个圆融合成有机形状
  • 理解 SDF 为什么能天然做描边、发光与柔和边缘

01距离就是形状

圆的 SDF 非常直观：length(p) - r。到原点的距离减去半径，小于 0 就在圆内，大于 0 就在圆外，等于 0 就是边界。你不需要三角形，也不需要顶点。

float sdCircle(vec2 p, float r) {
  return length(p) - r;
}

// 距离 < 0.01 的部分当作填充
float fill = smoothstep(0.01, 0.0, d);

smoothstep 把距离变成 0..1 的遮罩，天然带有柔和边缘；把参数收窄，就得到硬边；放宽，就得到发光。

02smooth min：形状会融合

两个 SDF 直接取 min，形状只是并集，交界处有硬折角。smin 在最小值附近做平滑混合，两个圆靠近时会像水滴一样连在一起——这就是 metaball 的手感。

float smin(float a, float b, float k) {
  float h = clamp(0.5 + 0.5 * (b - a) / k, 0.0, 1.0);
  return mix(b, a, h) - k * h * (1.0 - h);
}

float d = smin(smin(d1, d2, 0.42), d3, 0.42);

k 越大，融合范围越宽；k 越小，越接近普通 min。Demo 里的鼠标会带动一个圆，另外两个圆固定，三者的融合边界随鼠标实时变化。

像墨水滴在纸上互相晕开

每个圆是一滴墨水，smin 是纸张的晕染半径。离得远时各自独立，靠近时边缘先连起来，再慢慢融成一个整体。

类比到哪为止：墨水是物理扩散；smin 只是一个数学平滑，你可以随时把融合半径调到任意值。

03从 2D 到 3D

把 vec2 p 换成 vec3 p，圆就变成球，矩形变成盒子。3D SDF 是 surface raymarching 的核心：相机沿射线前进，每一步用 SDF 问「离最近表面还有多远」，直到距离足够小或超出范围。

🔬 深入：SDF 为什么会出现在字体、UI 和特效里？

因为距离场是分辨率无关的：同一个 SDF 可以在任意尺寸下重建边缘，还能用 smoothstep 自由控制描边宽度和发光。字体渲染（SDF font）、UI 圆角、图标发光、2D metaball 都爱用它。

代价是需要预计算或实时计算距离；复杂 3D 场景用 SDF 时，raymarch 的步数会直接影响性能。

案例 · 图标描边与液体融合

SDF 图标可以在任意分辨率下保持边缘锐利；metaball 加载动画、液体按钮，都是 smooth min 的日常应用。

04自测

SDF 返回负数代表什么？

点在形状内部。正数在外部，零在边界；绝对值是到边界的距离。

smin 和 min 的区别？

min 直接取较小值，边界有折角；smin 在交界处平滑混合，形状会自然融合，适合有机形体和 metaball。

为什么 SDF 做描边很方便？

因为 abs(d) 就是到边界的距离，用 smoothstep(宽度, 0, abs(d)) 就能得到一条固定宽度的边界带。

这一讲带走

SDF 把「形状」变成「距离函数」：负内正外，零是边界。smoothstep 负责上色，smin 负责融合。理解这一点，你就拿到了 raymarching 的钥匙。

第 7 讲 · 程序化图形

光照与 raymarch：球体怎么亮沿射线步进找到表面，用有限差分求法线，再用 dot 算明暗

SDF 只告诉你形状在哪，不会自动产生立体感。要给球体打光，需要三件事：从相机发射射线、找到交点、在交点处求法线，最后用光线方向与法线的点积算亮度。

Demo 7 · raymarch 球体 关键词 raymarch · normal · dot

  • 学完这一讲，你会
  • 用 SDF 步进找到射线与表面的交点
  • 用有限差分计算表面法线
  • 用 dot(normal, lightDir) 做出漫反射与边缘光

01从像素发射一条射线

全屏 shader 的每个像素对应相机的一条射线。把 UV 映射到 -1..1，乘宽高比，再组合相机位置和方向。Demo 里的相机固定在 z=3.2，射线朝 -z 方向发散。

vec2 uv = vUv * 2.0 - 1.0;
uv.x *= uRes.x / uRes.y;
vec3 ro = vec3(0.0, 0.0, 3.2);
vec3 rd = normalize(vec3(uv, -1.8));

02步进与法线

沿射线每次前进「当前点到最近表面的距离」。如果距离小于阈值，就认为命中；如果走太远，就认为没打中。命中后，用 SDF 在 x/y/z 三个方向的微小偏移求法线。

float map(vec3 p) {
  p.xz = rot(uTime * 0.25) * p.xz;
  return length(p) - 1.0;
}

vec3 calcNormal(vec3 p) {
  const vec2 e = vec2(0.001, 0.0);
  return normalize(vec3(
    map(p + e.xyy) - map(p - e.xyy),
    map(p + e.yxy) - map(p - e.yxy),
    map(p + e.yyx) - map(p - e.yyx)
  ));
}

有限差分是 raymarch 里最常用的法线求法：不需要解析导数，只要多采样几次 SDF。代价是每个像素多几次函数调用。

像在黑暗里用手电筒找墙

每一步问「我离最近的墙还有多远」，然后走那么远；走到足够近就停下。法线是墙面朝向，光照就是手电筒方向与墙面朝向的夹角。

类比到哪为止：真实手电筒会散射、有阴影；raymarch 的简单光照只算一个方向光，阴影要额外发射阴影射线。

03光照公式

漫反射用 max(dot(n, l), 0.0)：法线与光方向越接近，越亮。菲涅尔用 pow(1 - dot(n, -rd), 3)：视线越贴近表面，边缘光越强。两者叠加就有立体感。

vec3 n = calcNormal(p);
vec3 l = normalize(vec3(0.6, 0.8, 0.4));
float diff = max(dot(n, l), 0.0);
float rim = pow(1.0 - max(dot(n, -rd), 0.0), 3.0);
vec3 col = vec3(0.12,0.75,0.7) * diff
         + vec3(0.8,0.4,0.95) * rim * 0.7
         + vec3(0.02,0.03,0.08);
🔬 深入：raymarch 的性能瓶颈在哪里？

主要在「每个像素的步数 × 每步的 SDF 计算量」。球体很简单，几十步就能命中；复杂场景（多个 SDF、噪声位移）会让每步成本高很多。常用优化包括：限制最大距离、提前退出、降低分辨率、减少 SDF 复杂度、用包围盒跳过空白区域。

屏幕空间反射、体积雾、软阴影都是在这个循环里再加采样；每加一项，成本都会成倍上升。

案例 · 手办展示与角色转面

产品页的手办/角色展示需要稳定的法线与高光；raymarch 让「转动视角」不需要重导模型。

04自测

raymarch 每一步前进多少距离？

前进当前点到最近表面的 SDF 距离。因为这段距离内不会撞到任何表面，所以是安全的步长。

为什么法线可以用有限差分求？

法线是 SDF 的梯度方向；在 x/y/z 三个方向取微小偏移，计算函数值差，就近似得到梯度。

dot(n, l) 的结果范围与含义？

范围 -1..1；1 表示法线与光线同向（最亮），0 表示垂直（无漫反射），负数表示背光。通常用 max(...,0) 截断。

raymarch = 发射射线 + SDF 步进 + 交点法线 + 点积光照。它用数学函数代替网格，是 shader 作品里最灵活、也最吃性能的一类技术。

01鼠标坐标怎么传

浏览器给的是相对视口的像素坐标，shader 需要 0..1 的 UV。用 getBoundingClientRect() 把坐标映射到画布内，再把 y 翻转（WebGL 原点在左下）：

canvas.addEventListener("pointermove", (e) => {
  const r = canvas.getBoundingClientRect();
  pointer.x = (e.clientX - r.left) / r.width;
  pointer.y = 1.0 - (e.clientY - r.top) / r.height;
  gl.uniform2f(uMouse, pointer.x, pointer.y);
});

触摸屏用 Pointer Events 就能统一处理；如果要做拖拽/缩放，需要记录 pointerId 和初始位置，别把「移动鼠标」和「按下拖动」混在一起。

02分辨率与 DPR

CSS 宽高是显示尺寸，canvas 的 width/height 是像素尺寸。在 Retina 屏上如果直接用 CSS 尺寸，画面会糊；但完全按 DPR 放大，又会增加 4 倍像素。常见折中是限制 DPR 上限：

const dpr = Math.min(window.devicePixelRatio || 1, 1.5);
canvas.width = Math.floor(cssWidth * dpr);
canvas.height = Math.floor(cssHeight * dpr);
gl.viewport(0, 0, canvas.width, canvas.height);

shader 里的 uRes 应该传 canvas.width/height（像素尺寸），这样宽高比与采样密度都正确。窗口变化时用 ResizeObserver 重新设置，而不是只在初始化时算一次。

像用放大镜看画

DPR 是放大镜的倍数：放大能看清细节，但也要处理更多像素。限制 DPR 上限，等于在清晰度和性能之间选一个可接受的折中。

类比到哪为止：放大镜不会改变画的内容；DPR 会改变实际渲染分辨率，shader 里的高频图案在低 DPR 下更容易闪烁。

03暂停与恢复

页面里可能有多个 demo，滚出视口后继续 60fps 渲染纯属浪费。用 IntersectionObserver 在进入/离开视口时启动/停止 requestAnimationFrame；页面隐藏时也停掉。

new IntersectionObserver((entries) => {
  entries.forEach((en) => {
    if (en.isIntersecting) startLoop();
    else stopLoop();
  });
}, { rootMargin: "120px 0px" }).observe(canvas);

document.addEventListener("visibilitychange", () => {
  if (document.hidden) stopLoop(); else startLoop();
});

04shader 侧也有一些性能习惯

先降复杂度，再降分辨率

减少 raymarch 步数、减少 FBM 层数、避免在片元里做昂贵循环，通常比单纯降低分辨率更划算；分辨率下降会先损失清晰度。

另外，尽量把「每帧不变」的计算放到 JS 或 uniform，而不是每个片元重复算。shader 里一次多余的点积可能被几百万像素放大。

🔬 深入：为什么鼠标事件要节流/合并？

pointermove 触发频率可能高于 60Hz，如果每次都更新 uniform 并触发绘制，会浪费。通常只记录最新坐标，在下一帧统一上传；或者用 requestAnimationFrame 合并事件。UI 事件处理不应成为渲染循环的瓶颈。

05自测

为什么鼠标 y 坐标要 1.0 - normalizedY？

浏览器坐标原点在左上、y 向下；WebGL/UV 通常原点在左下、y 向上。翻转后才能让鼠标位置与画面一致。

canvas.width 和 CSS width 的区别？

CSS width 是显示尺寸；canvas.width 是实际像素缓冲尺寸。后者决定 GPU 渲染分辨率，前者只是布局。

为什么会用 IntersectionObserver 暂停 demo？

不可见的画面继续渲染会浪费 CPU/GPU 和电量。离开视口暂停、进入再恢复，是页面里有多个 WebGL demo 时的基本礼貌。

01场景就是多个 SDF 的并集

球体与圆环分别是一个距离函数，取 min 就得到「离任一物体最近」的距离。raymarch 不需要知道场景里有几个物体，它只需要一个 map(p)。

float map(vec3 p) {
  vec3 q = p;
  q.xz = rot(uTime * 0.18) * q.xz;
  float sphere = length(q) - 0.75;
  float torus = length(vec2(length(q.xz) - 1.35, q.y)) - 0.28;
  return min(sphere, torus);
}

圆环 SDF 的写法值得记住：先算 xz 平面到圆心的距离，再与 y 组成二维向量，减去管半径。这样圆环会绕 y 轴旋转，而不是平躺在屏幕上。

02给画面收尾

材质色、背景渐变、雾、暗角，这些「收尾」决定了画面是否像一件完整作品。一个简单的背景渐变就能让黑底上的几何体立刻有空间感。

vec3 col = vec3(0.015, 0.03, 0.08);
if (t < 9.0) {
  vec3 n = calcNormal(p);
  float diff = max(dot(n, normalize(vec3(0.5,0.9,0.3))), 0.0);
  float rim = pow(1.0 - max(dot(n, -rd), 0.0), 2.5);
  col = vec3(0.1,0.8,0.7) * diff
      + vec3(0.9,0.35,0.9) * rim * 0.8;
}
col += vec3(0.3,0.15,0.5) * smoothstep(0.8, 0.0, length(uv));
像搭一组静物摄影

几何体是摆件，光照是灯，背景是幕布，雾和暗角是镜头氛围。每件东西都简单，组合起来才成为一张照片。

类比到哪为止：摄影受物理约束；shader 里你可以随意让球和环互相穿插，只要距离函数写得出来。

03结课项目建议

  1. 换材质：给球和环不同颜色，或按法线方向混色。
  2. 加噪声：用 fbm 扰动 SDF 表面，做出岩石/液态金属质感。
  3. 加交互：鼠标控制旋转速度或相机位置，滚轮改变 fog 密度。
  4. 加后处理：把场景颜色做暗角、色调映射或扫描线，形成自己的风格。

04自测

两个 SDF 用 min 组合，表示什么？

表示两个形状的并集：空间中任意点到「最近的任一表面」的距离。raymarch 用这个距离安全前进。

圆环 SDF 里为什么要先算 length(q.xz)？

圆环可以看成「xz 平面上到圆心距离为 R 的圆」与「y 方向上的管截面」的组合；先算平面距离，再与 y 组成二维向量，才能得到正确的管状距离。

如果场景中有 3 个物体，map 应该返回什么？

返回三个 SDF 的最小值（或 smooth min）。raymarch 只关心最近表面距离，不关心物体数量。

013 渲 2 不是加一个滤镜

它是一套「主动做减法」的渲染策略：几何还是 3D，光照还是点积，但最后呈现时把连续亮度压成几档、把轮廓描出来、把阴影换成网点或排线。观众看到的不是「真实的 3D」，而是「动画里的 3D」。

像动画师给赛璐璐片上色

真实光照有无数层灰；赛璐璐动画只留「亮、中、暗」几块颜色，再用黑线勾边。shader 里的 cel shading 就是把这个手工流程写成数学：`floor` 负责分层，`smoothstep` 负责勾线。

类比到哪为止：动画师会按镜头手工调整色块；shader 是按像素自动算，所以需要额外处理描边粗细、锯齿和镜头运动。

02卡通光照：把亮度切成 3 档

先算普通的 Lambert 亮度，再把 0..1 的连续值量化到 0 / 0.5 / 1 三档。注意加一点 `smoothstep` 过渡，否则移动镜头时色阶边缘会严重锯齿。

float ndl = dot(n, l);
float tone = clamp(ndl * 0.5 + 0.5, 0.0, 1.0);
float cel = floor(tone * 3.0) / 2.0;   // 0.0 / 0.5 / 1.0
vec3 col = mix(shadowColor, baseColor, cel);

再叠一个硬高光：`pow(dot(n, halfDir), 48)` 超过阈值才显示，形成动画里常见的「一块白」。高光不要柔，柔了就像塑料而不是赛璐璐。

03描边：轮廓与细节线

最简单的外轮廓来自菲涅尔：视线越贴近表面切线，`1 - dot(n, -rd)` 越接近 1，把它压成一条暗边。它不需要第二个 pass，成本低，适合实时。

float rim = 1.0 - max(dot(n, -rd), 0.0);
float outline = smoothstep(0.55, 0.8, rim);
col = mix(col, vec3(0.02, 0.02, 0.05), outline * 0.9);
col += vec3(0.3, 0.85, 1.0) * pow(rim, 3.0) * 0.45;

星球条纹、环轨、卫星这类「内部装饰」不是几何轮廓，需要在材质阶段按局部坐标画；Demo 里的条纹和卫星就是根据命中点的位置直接上色。

04屏幕空间：半调与速度线

把 UV 放大成网点，只在暗部叠加，就是漫画里的半调阴影；把极坐标角度做成放射线，再乘一个径向遮罩，就是速度线。它们不是 3D 几何，而是「贴在镜头上的动画语言」。

vec2 hp = fract(vUv * vec2(aspect, 1.0) * 120.0);
float dots = step(0.35, length(hp - 0.5));
float shadowMask = 1.0 - smoothstep(0.2, 0.8, cel);
col *= 1.0 - dots * shadowMask * 0.25;

float ang = atan(sp.y, sp.x);
float speed = pow(0.5 + 0.5 * sin(ang * 60.0 + uTime * 1.8), 18.0)
            * smoothstep(0.1, 1.1, length(sp));
真实案例 · 动画与游戏里的卡通渲染

卡通渲染常见于动画电影、二次元游戏和风格化广告：角色用 cel shading，场景用轮廓线，特效叠半调/速度线。很多看起来「像手绘」的镜头，底层仍是 3D 模型 + 多 pass 后处理。

05如果模型是 OBJ / glTF 呢？

本课 Demo 用 SDF 生成角色，所以一切在片元里完成。真实项目里，3D 模型通常来自 Blender/OBJ/glTF，由 Three.js 或引擎加载，再用自定义材质替换默认光照：

  1. 拿到模型的 法线、世界坐标和深度，作为 varying/uniform 传给 shader。
  2. 在片元里做 cel 量化，而不是用引擎默认的 PBR。
  3. 轮廓线用「背面外扩」第二 pass，或基于深度的边缘检测；菲涅尔描边只是最便宜的近似。
  4. 半调/速度线放在后处理 pass，不要塞进模型材质。
🔬 深入：为什么风格化比写实更考验审美？

写实渲染有物理参照，方向相对明确；风格化要主动决定「丢掉什么、保留什么」：色阶分几档、线多粗、高光多大、阴影用什么图案。这些选择没有唯一正确答案，只能靠大量看片和对比。

技术上，3 渲 2 往往需要多 pass（模型、描边、后处理）和稳定的帧率；先把单 pass 的 cel + 菲涅尔描边做顺，再考虑更复杂的管线。

06自测

cel shading 里为什么要用 floor 而不是直接用 sin？

floor 把连续亮度切成离散的几档，形成「赛璐璐」色块；sin 是连续周期变化，会得到平滑渐变，不是卡通分层。

菲涅尔描边为什么在物体边缘最明显？

边缘处法线与视线接近垂直，dot(n,-rd) 接近 0，1-dot 接近 1；中心处法线朝向相机，值接近 0。

真实 glTF 模型的描边，为什么常用背面外扩 pass？

菲涅尔描边只能画「朝向相机的轮廓」，对内部折角/遮挡边界不够稳定；背面外扩沿法线扩大模型再画背面，能得到更均匀、可控粗细的轮廓。

这一讲带走

3 渲 2 = 几何 + 量化光照 + 轮廓线 + 屏幕空间图案。它不是「真实感的降级」，而是一套独立的视觉语言。你现在可以把任意 3D 场景压成动画截图，也可以继续往多 pass 和后处理走。

课程结束：挑一个你喜欢的模型，先用 cel + 描边跑起来，再决定要不要加半调、速度线或色差。风格是你自己选的。
