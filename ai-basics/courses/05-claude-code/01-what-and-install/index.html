L1第 1 课

Claude Code 是什么

terminal-native harness 的定位、安装、登录与第一次会话

💡

为什么

很多人第一次接触 Claude Code，会把它归类成两种东西之一：IDE 里的补全插件，或者一个能聊天的编程助手。两种归类都不准确。

Claude Code 是 Anthropic 的 terminal-native coding harness：它住在终端里，直接读你的仓库、改文件、跑命令、用 git。它不是一个更聪明的补全框，而是一个以任务为单位工作的 Agent 运行时。

这个区别决定了三件事：

  1. 工作单位不同——补全以「光标处下一段代码」为单位；Claude Code 以「把这件事做完」为单位，可能横跨多个文件、多轮工具调用。
  2. 上下文不同——补全只看当前文件和邻近片段；Claude Code 能读整个仓库、跑测试、看报错，再回来改。
  3. 风险面不同——它真的会写盘、真的会执行命令，所以权限边界是这门课的主线，而不是可选项。
✨

一句话定位：IDE 补全负责「你正在写的这一行」，Claude Code 负责「你交给它的这一件事」。

🖼️

可视化

三种形态，边界很清楚：

💡
  • IDE 补全（Copilot 类）：在编辑器里预测下一段代码，低延迟、单人、局部。你始终是执行者。
  • 聊天框（Chat UI）：你贴代码、它给建议，结果要你手动搬回仓库。它不接触你的文件系统。
  • terminal-native harness（Claude Code）：在你自己的 shell 里运行，直接读文件、写文件、跑命令、用 git。它是执行者，你是审批者与验收者。

三者不是替代关系。补全适合「边写边补」，聊天适合「问概念、要方案」，Claude Code 适合「这件事你帮我从头做到尾，我来看 diff」。

🧮

形式化

把 Claude Code 拆成五个部件，后面每一课都会回到这张图：

💡
  1. 模型：Claude 本体，负责推理并决定下一步调什么工具。
  2. 工具层：Read / Write / Edit / Bash / Glob / Grep / WebFetch / Task / TodoWrite 等内置工具。
  3. 权限层：决定某个工具调用是自动放行、询问你，还是直接拒绝。
  4. 上下文层：CLAUDE.md、会话历史、工具结果，共同组成每轮喂给模型的内容。
  5. 会话层：把一次任务的消息与工具结果持久化，支持压缩与续接。

所以它既不是「模型」，也不是「插件」，而是把模型、工具、权限、上下文、会话组织成一个循环的运行时。这就是 harness 的含义。

「terminal-native」还有一层工程含义：当前工作目录就是它的工作范围。你在哪个仓库目录启动 claude，它默认就在那个仓库里活动，Bash 也继承你的 shell 环境。这让它天然贴合「读代码 → 改代码 → 跑测试」的闭环，而不是把代码复制到另一个界面里。

首次会话的顺序通常是：启动 → 登录 → 选模型 → 让它理解仓库 → 开始任务。/init 是让仓库「自我介绍」的一步：它扫描项目结构、命令与约定，生成一份 CLAUDE.md，作为之后每轮对话的常驻上下文。

🛠️

动手

安装（需要 Node.js 18+，以官方文档的版本要求为准）：

bash
npm install -g @anthropic-ai/claude-code

官方也提供原生安装脚本（macOS / Linux / Windows 各有入口），适合不想维护全局 npm 包的环境；具体命令以官方安装文档为准。

安装后在你的仓库根目录启动：

bash
cd /path/to/your-repo
claude

首次进入会要求登录，然后用 /model 选择模型：

text
/login
/model

登录后先让仓库生成自己的说明书：

text
/init

⚠️

要点回顾

  • Claude Code 是 terminal-native harness，不是 IDE 插件，也不是聊天框。
  • 五个部件：模型、工具、权限、上下文（CLAUDE.md）、会话。
  • 首次流程：安装 → claude → /login → /model → /init。
  • 与补全分工：局部补全归 IDE，任务级交付归 Claude Code。
