实战演练

从读代码到补测试、跑通、review diff 的完整闭环

💡

为什么

会敲命令，不等于会用它干活。真实的差距在流程：先读还是先改？什么时候该进 plan 模式？测试红了怎么办？diff 里哪些东西必须人看？

这一课用一个完整任务把前面的东西串起来：给一个模块补单元测试并跑通。任务不大，但覆盖了读、改、跑、审四个环节，也覆盖了权限、上下文、git 三条主线。

✨

衡量一次 Agent 交付，不看它「改了多少行」，而看三件事：改动是否最小、验证是否真实、diff 是否可审。

🧮

形式化

阶段 0：准备

确认工作区干净（git status），从主分支切一个专用分支。若仓库还没有 CLAUDE.md，先 /init 并删减，保证模型知道测试命令与约定。

阶段 1：读

用 plan 模式或只读工具集，让它先回答三个问题：模块的公开接口是什么？现有测试用什么框架、什么风格？测试命令是什么？检查点：它能准确复述接口与测试命令，而不是泛泛而谈。

阶段 2：改

批准后再进入执行。要求它一次只改一个文件，优先新增测试文件，而不是重写实现。检查点：git diff 里只出现预期文件。

阶段 3：验证

跑项目自己的测试命令（本仓库是 pnpm test）。检查点：全部通过，且测试确实断言了行为——警惕为了变绿而弱化断言。

阶段 4：review diff

看 git diff，确认没有顺手改无关文件、没有留下调试输出、没有跳过测试。提交由你确认后执行；推送前再看一眼分支。

💡

一个常见误区：把「测试通过」当成验收终点。通过只说明当前断言满足；你还要看断言是否覆盖了真正重要的行为，否则只是把 bug 固化成了预期。

🛠️

动手

准备分支，并用 plan 模式启动：

bash
git switch -c test/tokenizer
claude --permission-mode plan

先只读，不落盘：

text
先只读 src/lib/tokenizer.ts 和现有测试，告诉我测试命令与测试风格，不要改任何文件。

思路确认后，再允许它动手：

text
按现有风格补 src/lib/tokenizer.test.ts，覆盖 tokenize 的边界情况；改完运行测试直到通过。

自己再跑一遍验证：

bash
pnpm test

审查改动，确认范围与质量：

bash
git diff --stat
git diff

确认无误后再提交（不要替用户决定提交时机）：

bash
git add src/lib/tokenizer.test.ts
git commit -m "test: cover tokenizer edge cases"

这是一段预录的 Claude Code 会话 trace，用于观察 harness 的完整链路：模型决策 → 权限检查 → 工具执行 → 结果回填 → 再决策。它不会在浏览器里运行真实 CLI。

对照 trace 复盘：第 2–4 步是「读」，第 5–7 步是「改」（注意写文件需要你批准），第 8–11 步是「验证与修正」，第 12 步才是交付。测试失败没有让流程中断，反而成了模型的输入——这正是 harness 循环的价值。

⚠️

常见失败与排错

  • 权限被拒：检查 .claude/settings.json 的 deny/ask 规则与当前权限模式；只读任务用 --allowedTools 收窄，而不是开 bypassPermissions。
  • 上下文爆了：先 /context 看占用，再 /compact；任务太大就拆小，或 /clear 开新会话重来。
  • 改错文件：在提示里写死路径；先用 Glob/Grep 确认；用 git diff 及时止损。
  • 测试环境不同：用项目脚本而不是自创命令；确认 Node 版本与依赖已安装，必要时在容器里跑。

团队落地建议

💡
  • 把 CLAUDE.md、.claude/commands/、项目级 settings.json 一起提交，让团队共享同一套约定与护栏。
  • 个人偏好与密钥放 .claude/settings.local.json，不要提交。
  • 用 hooks 做审计与危险命令拦截，用 skills 固化重复的 runbook，用 project scope 的 MCP 接内部系统。
  • 把 Agent 的 diff 当人类 PR 审：范围、断言、副作用，一项都不能省。

要点回顾

  • 四阶段：准备 → 只读 → 修改 → 验证 → review diff，每阶段都有检查点。
  • 先 plan 后执行，写操作要人批准；测试失败是反馈，不是中断。
  • 排错四类：权限、上下文、改错文件、环境不一致。
  • 团队落地：共享 CLAUDE.md / 命令 / 配置，个人覆盖进 local，diff 当 PR 审。
