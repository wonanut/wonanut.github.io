L3第 2 课

会话与 CLI 模型

上下文如何累积，以及如何把 CLI 当脚本、管道与 CI 使用

💡

为什么

学会了启动，第二个问题是：一次「对话」到底是什么？

在 Claude Code 里，会话不是聊天记录，而是一份持续增长的工作上下文：你的指令、模型的决策、每次工具调用的结果，都会追加进去，下一轮再整体参与推理。理解这一点，你才能回答三个很实际的问题：

  1. 为什么聊久了会变慢、变贵？——上下文在累积。
  2. 为什么 /clear 和 /compact 不是一回事？——一个丢弃，一个摘要。
  3. 为什么同一句提示，脚本里跑和终端里跑行为不同？——交互会话会续接历史，-p 是一次性的。
✨

把会话想成一张不断变长的桌子：每轮工具结果都往桌上堆一张纸。桌上放不下时，你要么清桌（/clear），要么把旧纸收成摘要（/compact）。

形式化

① 会话里到底有什么

每轮送给模型的内容，大致由四层拼成：

💡
  • 系统提示与工具定义：harness 固定的指令和工具 schema。
  • 项目记忆：CLAUDE.md 等上下文文件，启动时加载。
  • 历史消息：你说的话、模型的回复、每次工具调用的结果。
  • 压缩摘要：上下文接近上限后，旧历史被摘要替换，但保留结论与待办。

历史会持续累积，所以「聊得越久越慢」不是模型变笨，而是输入变长。实际实现会用 prompt caching 降低成本，但语义上仍然是「历史 + 新输入」一起参与推理。

② 三个命令，三种语义

  • /context：查看当前上下文的占用明细，先量再治。
  • /compact：把历史压成摘要后继续，任务不中断。
  • /clear：清空当前会话，从零开始，适合切换到不相关的任务。

③ 非交互模式 -p

claude -p "..." 是一次性调用：读入提示（也可从 stdin 读），执行完把结果打到 stdout，进程退出。它不进 TUI、不等人确认，因此适合脚本、管道和 CI。

④ 续接

  • claude --continue：直接续上当前目录最近一次会话。
  • claude --resume：打开会话列表，手动挑一条继续。

两者都依赖会话持久化。跨目录时，--continue 找的是当前目录的会话，不要指望它串到别的仓库。

⑤ 把 CLI 当脚本用

三条工程原则：

  1. 输入走 stdin、输出走 stdout，才能进管道。
  2. 用 --output-format json 拿结构化结果，别用正则解析人类可读文本。
  3. 用 --allowedTools 收窄能力，CI 里尤其不要给不需要的写权限。
🛠️

动手

交互式会话，最常用的起点：

bash
claude

一次性提问，不进入 TUI：

bash
claude -p "解释 src/lib/tokenizer.ts 的 encode 逻辑"

把 diff 通过管道喂给它做总结：

bash
git diff | claude -p "用三句话总结这次改动，并指出一个风险"

脚本里要结构化结果时：

bash
claude -p "列出 src 下没有被引用的导出" --output-format json

CI 里做只读检查，显式收窄工具：

bash
claude -p "检查是否有遗留的 console.log" --allowedTools "Read" "Grep" "Glob"

续接上一段工作：

bash
claude --continue

从历史会话里挑一条：

bash
claude --resume

会话中的三个上下文命令：

text
/context
/compact
/clear
⚠️

在 CI 里跑 -p 时，注意两件事：一是工作目录必须是仓库根，否则读不到项目记忆；二是权限要提前收窄，非交互环境没人能点「批准」，被 ask 拦下的调用会直接失败。

要点回顾

  • 会话是持续增长的上下文：系统提示、CLAUDE.md、历史、工具结果、压缩摘要。
  • /context 看占用，/compact 摘要续跑，/clear 清空重来。
  • -p 非交互，配 stdin/stdout、--output-format json、--allowedTools 用于脚本与 CI。
  • --continue 续最近一次，--resume 选历史会话，均按当前目录生效。
