CLAUDE.md 上下文工程

三层记忆、写什么与不写什么，以及如何与 AGENTS.md 共存

💡

为什么

上下文是稀缺资源。CLAUDE.md 会被每一轮带上，所以它既是最划算的投资，也是最容易变成负债的文件。

一份好的 CLAUDE.md 像给新同事的交接文档：命令是什么、约定是什么、哪里不能碰。一份坏的 CLAUDE.md 则像把整本维基百科塞进每轮对话：占满预算、夹带过期信息，还让模型抓错重点。

这一课解决三个问题：放哪、写什么、怎么维护。

✨

判断一条信息该不该进 CLAUDE.md，只问一句：它是否每轮都值得占用上下文？ 答案否，就该放进文档链接、skill 或子目录文件里。

🖼️

可视化

三层记忆，从通用到具体：

💡
  • 用户级 ~/.claude/CLAUDE.md：你个人的跨项目偏好，例如回复语言、常用命令风格。只影响你自己。
  • 项目级 ./CLAUDE.md：团队契约，提交进仓库。放构建/测试命令、目录约定、禁区、架构决策。
  • 子目录 ./packages/api/CLAUDE.md：只在处理该子树时按需加载。放这个模块特有的约定与坑。

三层是叠加关系：项目级补充用户级，子目录级补充项目级。越靠近当前工作目录，内容越具体。

除了文件本身，还可以用 @path 把别的文件导入进来，把「常驻内容」和「按需文档」解耦。

🧮

形式化

① 三层怎么分工

💡
  • 用户级：只放跨项目都成立的东西。项目特有的命令不要写在这里。
  • 项目级：放团队必须一致的东西。命令、技术栈、目录结构、代码规范、禁止事项。
  • 子目录级：放局部知识。这个包的测试怎么跑、生成代码在哪、有哪些历史包袱。

子目录文件的价值在于按需加载：处理 packages/api 时才有成本，不相关的工作不会被它拖累。

② 写什么

  • 命令：安装、测试、构建、lint 的准确命令。这是收益最高的一类信息，模型不用猜。
  • 约定：命名、目录、错误处理、测试风格。让产出和现有代码一致。
  • 禁区：生成文件不要手改、不要提交密钥、不要动迁移文件、共享分支不要 force push。
  • 架构决策：为什么这样分层、哪些边界不能跨。避免模型「好心重构」破坏设计。
  • 常见坑：环境变量、端口、需要先启动的服务。

③ 不写什么

⚠️
  • 易过期的细节：具体版本号、依赖清单、随时会变的接口字段。这些以 package.json 和代码为准。
  • 大段文档：完整 API 手册、长篇设计文档。给链接或放进 @path 导入的文件。
  • 显而易见的话：「要写测试」「注意安全」这类没有操作性的口号。
  • 密钥与个人信息：CLAUDE.md 会进仓库，也会进模型上下文。
  • 与代码重复的内容：重复就会漂移，漂移就会误导。

④ 生成与维护

/init 会扫描仓库生成初稿，但它只是起点，必须人工删减。之后用 /memory 打开记忆文件编辑。把 CLAUDE.md 当成代码一样 review：改架构时同步改它，发现模型反复犯同一个错，就补一条明确规则。

⑤ 与 AGENTS.md 的关系

AGENTS.md 是跨工具的共同约定，很多编辑器与 Agent 都认它。Claude Code 以 CLAUDE.md 为主，但你可以用 @AGENTS.md 把它导入，让两份共享同一份事实，避免各写一套、逐渐漂移。

🛠️

动手

一个典型项目的记忆布局：

text
repo/
├── CLAUDE.md                 # 项目级：命令、约定、禁区
├── .claude/
│   ├── settings.json         # 权限与 hooks
│   └── commands/review.md    # 自定义命令
├── packages/
│   ├── api/CLAUDE.md         # 子目录级：只在处理 api 时加载
│   └── web/CLAUDE.md
└── ~/.claude/CLAUDE.md       # 用户级：跨项目偏好

一份克制的项目级 CLAUDE.md 示例：

text
# 项目约定

## 命令
- 安装依赖：pnpm install
- 测试：pnpm test
- 构建：pnpm build

## 约定
- React 组件放 src/components，按功能分目录。
- 测试与实现同目录，命名为 *.test.ts。
- 提交前必须跑 pnpm test。

## 禁区
- 不要手改 src/generated 下的文件。
- 不要提交 .env 或任何密钥。
- 共享分支不要 force push。

## 架构
- 内容层在 content/，渲染层在 src/，两层不要互相引用。
@AGENTS.md

生成与维护：

text
/init
/memory

提示：/memory 会打开记忆文件供你编辑；/init 生成后记得删掉它猜错或过期的内容。

💡

如果团队已经维护 AGENTS.md，最省事的做法是让 CLAUDE.md 只放 Claude Code 特有的部分，其余用 @AGENTS.md 导入。两份文件各司其职，而不是互相复制。

要点回顾

  • 三层记忆：用户级、项目级、子目录级，越靠近工作目录越具体。
  • 写命令、约定、禁区、架构决策、常见坑；不写易过期细节、大段文档、密钥。
  • /init 生成初稿，/memory 维护；@path 可导入 AGENTS.md 等文件。
  • 判断标准：这条信息是否每轮都值得占用上下文。
