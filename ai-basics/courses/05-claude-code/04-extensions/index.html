L0第 4 课

扩展机制：MCP / hooks / slash commands / skills

四种扩展面各自解决什么问题，以及怎么选

💡

为什么

内置工具能覆盖「本地仓库里读、改、跑」，但真实团队总会撞到四类需求：

  1. 接外部系统——查 Jira、读监控、访问内部知识库；
  2. 加护栏——危险命令自动拦、每次编辑后自动格式化；
  3. 固化流程——「发版前检查」这种人人都在重复的多步操作；
  4. 教方法——让模型按团队约定的步骤完成一类任务。

Claude Code 对应给了四种扩展面：MCP、hooks、slash commands、skills。它们不是互相替代，而是分别改运行时的不同层。

🖼️

可视化

四者各改一层，记这张表就不会混：

💡
  • MCP：扩展能力边界——把外部工具和数据接进来，让模型能调用本地没有的东西。
  • hooks：扩展控制边界——在固定的生命周期节点自动执行脚本，可审计、可拦截。
  • slash commands：扩展交互入口——把一段固定提示词包装成命令，由你主动触发。
  • skills：扩展知识供给——把一类任务的方法论写成文件，由模型按需加载。

一句话：MCP 让模型「够得着」，hooks 让流程「管得住」，slash commands 让你「叫得动」，skills 让模型「做得对」。

🧮

形式化

① MCP：把外部系统变成工具

MCP（Model Context Protocol）是一套连接外部工具与数据源的协议。接入后，外部能力会以工具的形式出现在模型面前，调用方式和内置工具一致。

💡
  • 添加：claude mcp add <name> -- <command>
  • 查看：claude mcp list
  • 三种 scope：local（默认，仅当前项目当前用户）、project（写入 .mcp.json，可提交给团队共享）、user（跨项目，当前用户全局）。

项目级配置落在仓库根的 .mcp.json，适合团队共享「这个项目需要哪些 MCP server」。

② hooks：在生命周期节点插脚本

hooks 写在 settings.json 里，由 harness 在固定事件触发。常用事件：

  • PreToolUse / PostToolUse：工具执行前 / 后。前者可阻止或放行调用，后者适合审计、格式化、补充反馈。
  • UserPromptSubmit：用户提交提示后、模型处理前，可注入额外上下文。
  • Notification：需要通知用户时触发。
  • Stop / SubagentStop：主 Agent / 子 Agent 结束时，可做最终检查。
  • SessionStart / SessionEnd：会话开始 / 结束，适合注入环境信息、归档日志。
  • PreCompact：上下文压缩前，适合保留关键状态。

hook 从 stdin 读取事件 JSON，通过退出码或 JSON 输出给出决定；PreToolUse 可以直接阻止一次工具调用。这让「危险命令拦截」不再依赖模型自觉。

③ slash commands：把提示词变成命令

内置命令包括 /init、/clear、/compact、/model、/context、/mcp、/agents、/hooks。自定义命令放在 .claude/commands/<name>.md，文件名就是命令名，正文就是提示词，$ARGUMENTS 接收调用时传入的参数。

④ skills：按需加载的方法论

一个 skill 是 .claude/skills/<name>/SKILL.md，frontmatter 至少包含 name 和 description。description 决定模型「什么时候该用它」；正文是具体步骤。启动时只加载元数据，命中场景才读正文，这就是渐进加载——不相关的能力不占上下文。skills 也可以通过 plugin 分发。

💡

附：子 Agent。自定义子 Agent 放 .claude/agents/<name>.md，frontmatter 声明 name / description / tools / model；主 Agent 通过 Task 工具委派子任务，可隔离上下文并限制工具范围。

⑤ 怎么选

  • 要接外部系统或数据 → MCP
  • 要在固定时机自动执行或拦截 → hooks
  • 要人主动触发一段固定流程 → slash commands
  • 要教模型一类任务怎么做、且按需加载 → skills
🛠️

动手

接入一个本地文件系统 MCP server，并确认它已注册：

bash
claude mcp add filesystem -- npx -y @modelcontextprotocol/server-filesystem /path/to/dir
bash
claude mcp list

想让团队共享，就把 scope 设为 project（写入 .mcp.json）：

bash
claude mcp add --scope project filesystem -- npx -y @modelcontextprotocol/server-filesystem /path/to/dir

用 hook 在每次 Bash 调用前跑一道检查：

json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": ".claude/hooks/guard-bash.sh" }
        ]
      }
    ]
  }
}

自定义一个审查命令，文件放在 .claude/commands/review.md：

text
---
description: 审查当前改动
---

审查当前的 git diff，重点看正确性、边界条件与测试覆盖。
额外关注：$ARGUMENTS

调用时传参：

text
/review 关注并发安全

一个最小 skill，文件放在 .claude/skills/release-check/SKILL.md：

text
---
name: release-check
description: 发布前检查版本、变更日志与回归测试；当用户提到发布、release 或上线时使用
---

1. 读取 package.json，确认版本号已更新。
2. 检查 CHANGELOG 是否有对应条目。
3. 运行 pnpm test 与 pnpm build。
4. 汇总结果，失败则停止并报告。
⚠️

hook 脚本和 MCP server 都是你引入的代码，它们以你的权限运行。接入前看清来源，别把来路不明的脚本配进 settings.json。

要点回顾

  • MCP 接外部能力，项目级配置在 .mcp.json，scope 分 local / project / user。
  • hooks 挂在生命周期事件上，PreToolUse 可拦截，PostToolUse 适合审计与格式化。
  • 自定义命令在 .claude/commands/<name>.md，用 $ARGUMENTS 传参。
  • skill 是 .claude/skills/<name>/SKILL.md，靠 description 被模型按需调用，渐进加载。
