会话树：分支与压缩

会话的数据结构、分支三操作与压缩算法

💡

为什么

大多数对话式工具把会话当成一条直线：你只能往后说，想「回到某个点重新来」只能开个新会话，丢了上下文。

Pi 把会话做成了树——这不仅是交互体验，更是一个数据结构设计：会话里的每一条记录（消息、工具结果、模型切换……）都是一个节点，通过 id 和 parentId 连成树，另有一个 leaf 指针标记「当前位置」。

这带来两个能力：

  1. 分支（branch）：从任意历史节点长出新的子路径，试另一种做法；
  2. 压缩（compaction）：上下文快塞满时，把旧历史压成摘要，腾出空间。
✨

树 + 压缩，解决的是同一个根本问题：上下文窗口是有限的，但长任务要「可回溯」又「可延续」。这是面试考察 Agent 记忆管理时的核心考点。

🖼️

可视化

从「用户请求」出发，模型先 read，之后可以 edit 改版本号，也可以分叉去 bash 测试；甚至可以回到更早的节点，走 write 新文件 的另一条路。

把鼠标移到节点上，看它代表哪一步（可分支）。

🧮

形式化

① 数据结构：entry 树 + leaf 指针

会话文件存的是一个 entry 树，节点用 id / parentId 相连；leaf 指针指向当前位置，「追加」就是给当前 leaf 生一个子节点。entry 的类型不止消息：

💡
  • 消息（user / assistant / tool result）
  • 模型切换、思考级别切换
  • 压缩摘要、分支摘要
  • 自定义 entry、标签

关键点：模型只接收 active branch（从根到 leaf 的那条祖先链），不是整个树。所以分叉不会把没走的分支喂给模型，上下文始终干净。

② 三个分支操作，语义不同

💡
  • /tree：在同一个会话文件内移动 leaf 指针——相关的多种尝试放在一起，方便对比；
  • /fork：从更早的某条用户消息，新建一个会话——独立的工作；
  • /clone：把当前 active branch 复制到一个新会话——保留当前状态的独立副本。

三者都是移动/复制 leaf 指针，不删除历史——这是「可回溯」的保证。

③ 分支摘要（branch summary）

用 /tree 从一条分支切走时，Pi 会提议把你要离开的这段工作做个摘要，挂到你要进入的分支上。算法是：

text
1. 找 old leaf 与 new leaf 的公共祖先（最深共同节点）
2. 从 old leaf 一路回溯到公共祖先，收集这些 entry
3. 在 token 预算内做摘要
4. 在导航点挂一个 BranchSummaryEntry

这样，被放弃分支里的有效工作被保留，但不必把每条消息都带过去。

④ 压缩（compaction）

当 active context 逼近模型上限时，Pi 会自动压缩较旧的历史：加一份摘要 + 保留最近的消息，但不删除原始 entry（原始记录还在，可回溯）。

💡

默认参数：compaction.enabled 开启；reserveTokens 预留约 16384 token 再触发；keepRecentTokens 保留最近约 20000 token。手动触发用 /compact，可带自定义指令。

压缩的切点规则是重点：

  • 在 turn 边界（user / assistant / BashExecution / 自定义消息）处切；
  • 绝不在 tool result 中间切——一个 turn 是原子的，从中间切会丢掉模型赖以继续的「工具结果」上下文；
  • 若单个 turn 本身就超过 keep-recent 预算，成为 split turn，生成两份摘要：历史摘要 + turn 前缀摘要。

摘要用结构化格式，不是拍脑袋一段话：

💡
  • Goal（目标）、Constraints & Preferences（约束与偏好）
  • Progress：Done / In Progress / Blocked
  • Key Decisions（关键决策）、Next Steps（下一步）
  • 压缩摘要额外有 Critical Context（关键上下文）
  • 附 <read-files> / <modified-files> 文件清单

实现细节：消息序列化成文本后（如 [User]: ...）再摘要；tool result 截断到 2000 字符、thinking 块省略；文件追踪在多次压缩和嵌套分支摘要间累积。扩展可以监听 session_before_compact 事件来取消压缩或提供自定义摘要。

🛠️

动手

在 TUI 里对应的交互入口：

💡
  • /tree：在当前会话内移动（离开时可触发分支摘要）
  • /fork：从历史消息新建会话
  • /clone：复制当前分支到新会话
  • /compact：手动压缩，可带自定义指令
⚠️

不同版本的 Pi 对分支/压缩的交互入口略有差异，以 pi --help 和官方文档为准。核心概念——entry 树 + leaf 指针、切在 turn 边界、结构化摘要——是稳定的，也是面试真正考的东西。

要点回顾

  • 会话是 entry 树（id/parentId）+ leaf 指针，模型只收 active branch。
  • 分支三操作：/tree 移动、/fork 新会话、/clone 复制；都不删历史。
  • 压缩：切在 turn 边界、绝不在 tool result 中间切、结构化摘要、保留原始记录。
