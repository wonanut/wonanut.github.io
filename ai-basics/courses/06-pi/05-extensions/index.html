L0第 5 课

扩展：skills / extensions / providers

ExtensionAPI、事件钩子与 models.json 的完整定制面

💡

为什么

Pi 核心只有四个工具，那子 Agent、MCP、权限门禁这些能力从哪来？

答案是扩展（extension）：核心保持最小，能力靠「外挂」按需加载。对专业工程师来说，这带来两个实打实的好处：

  1. 核心永远简单可懂——你能对整个运行时做安全推理；
  2. 你的项目只背负它真正用到的能力——不被一堆用不上的功能拖累攻击面和复杂度。

本课把「定制面」讲透：从最轻的 Skills，到最强的 Extensions，再到决定「用哪个模型」的 Providers。

🖼️

可视化

四层定制，从「最轻」到「最重」：

💡
  • Skills（技能）：Markdown + YAML 写成的「操作手册」，教模型怎么完成一类任务。最轻量。
  • Prompt Templates（提示词模板）：预置的角色/工作流提示词，快速切换「人格」。
  • Extensions（扩展）：TypeScript 写成的插件，通过 ExtensionAPI 给 harness 加新工具、钩子、中间件。功能最强。
  • Packages（包）：把 skill / extension / 配置打包成 npm 包，一次分发、一行安装。

一句话分层：Skills 教模型怎么做，Extensions 改 harness 能做什么，Providers 决定用哪个模型。

🧮

形式化

① Skills：本质是提示词注入

一份结构化的 Markdown（带 YAML frontmatter），告诉模型「在什么场景、按什么步骤、用什么工具」。不改任何代码——它改变的是模型收到的提示词。

② Extensions：本质是运行时挂钩

一个扩展是一个 TS 文件，export default 一个接收 ExtensionAPI 的函数：

ts
import { Type } from "@sinclair/typebox";

export default function (pi) {
  pi.registerTool({
    name: "calculate",
    description: "Perform calculations",
    parameters: Type.Object({ expression: Type.String() }),
    async execute(_id, params) {
      return { content: [{ type: "text", text: `Result: ${params.expression}` }] };
    },
  });
}

三个要点：

💡
  • 注册工具：pi.registerTool({ name, description, parameters, execute })，参数用 TypeBox 定义 JSON Schema，返回 { content: [{ type: "text", text }], details?, isError? }。
  • 事件钩子：pi.on("event", async (event, ctx) => ...) 订阅生命周期事件。
  • 工具管理：getActiveTools() / getAllTools() / setActiveTools(names) 动态增删模型可见的工具。

事件钩子列表（面试常考「你会挂哪个钩子做 X」）：

💡
  • 工具链：tool_execution_start → tool_call（可改/拦）→ tool_execution_update → tool_result（可改结果）→ tool_execution_end
  • 会话/请求：session_start、before_agent_start、context、before_provider_request、after_provider_response、message_start/update/end、turn_end、agent_end、project_trust、session_before_compact

一个经典的「权限门禁」就是靠 tool_call 拦截实现的：

ts
pi.on("tool_call", async (event, ctx) => {
  if (isToolCallEventType("bash", event)) {
    if (event.input.command.includes("rm -rf")) {
      return { block: true, reason: "Dangerous command" };
    }
  }
});

这正印证了第 1 课的说法：Pi 默认不内置权限门禁，但你可以用扩展自己实现——拦截、改写、放行，规则由你定。

③ Providers：models.json

「用哪个模型、怎么认证、跑在哪」由 ~/.pi/agent/models.json 决定（可用 PI_CODING_AGENT_DIR 改目录）：

json
{
  "providers": {
    "ollama": {
      "baseUrl": "http://localhost:11434/v1",
      "apiKey": "OLLAMA_API_KEY",
      "api": "openai-completions",
      "models": [
        { "id": "llama-3.1-8b", "cost": { "input": 0, "output": 0 },
          "contextWindow": 128000, "maxTokens": 32000 }
      ]
    }
  }
}

要点：

💡
  • api 类型：openai-completions / anthropic-messages / openai-responses / google-generative-ai / mistral-conversations。
  • apiKey 支持环境变量引用（如 $MY_KEY，先查 process.env 再当字面量）。
  • 覆盖内置 provider：只写 baseUrl 即可走代理，内置模型保留；写 models 则按 id upsert 合并（同 id 覆盖、新 id 追加）。
  • modelOverrides 做单模型微调（name/cost/contextWindow 等）；compat 处理 provider 兼容性差异。
🛠️

动手

切换模型：TUI 里按 Ctrl+L 或输入 /model；CLI 用 --provider / --model / --api-key。想手动改配置，去看：

text
~/.pi/agent/models.json
⚠️

扩展 API 的某些签名（如 execute 的参数个数）可能随版本演进，写扩展时以安装版本的 TypeScript 类型定义为准。理解「四层定制」的分层与 tool_call 拦截这个核心模式，比记住某个具体签名更重要。

要点回顾

  • 四层定制：Skills（提示词）/ Prompt Templates / Extensions（代码）/ Packages（分发）。
  • ExtensionAPI：registerTool（TypeBox 参数）+ pi.on 事件钩子 + setActiveTools 动态开关。
  • tool_call 拦截是实现权限门禁的标准模式。
  • Providers 用 ~/.pi/agent/models.json 配置，按 id upsert 合并，支持 env 引用。
