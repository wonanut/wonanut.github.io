L0第 6 课

与 Claude Code 对比

设计取向的取舍与选型决策框架

💡

为什么

学到这里，一个自然的问题：Pi 和 Claude Code 到底怎么选？

两者都能「让模型读代码、改代码、跑命令」，但设计哲学截然相反。面试里，这是一道经典的系统设计取舍题——考官不关心你背出谁「更好」，而关心你能不能讲清两者在哪些维度上、为什么做了相反的选择。

记住一条：没有绝对更好，只有更适合你的场景与约束。

🖼️

可视化

两者最根本的分歧，是「核心该有多大、能力放在哪」：

💡
  • Claude Code：功能齐全的开箱即用工具，内置计划模式、子 Agent、MCP、权限门禁、后台任务等，定位是「拿来即用的完整助手」。
  • Pi：刻意做小的 harness，核心只有循环 + 四个工具 + TUI + 会话管理，其余靠扩展，定位是「你能重塑的最小核心」。

一个把「聪明」做进产品，一个把「聪明」留给模型和你的扩展。

🧮

形式化

逐维度对比（Pi 默认情况）：

💡
  • 内置能力：Pi 少而精；Claude Code 多而全（计划模式、子 Agent、MCP、权限系统、后台任务开箱即有）。
  • 权限模型：Pi 无内置门禁，靠扩展在 tool_call 拦截自建；Claude Code 内置权限系统 + hooks，默认就有 allow/deny 边界。
  • 子 Agent：Pi 靠扩展拼装；Claude Code 内置 Task 子 Agent 委派。
  • MCP：Pi 靠扩展接入；Claude Code 内置支持。
  • 压缩/上下文：两者都做上下文管理，但 Pi 把它做成可观测、可挂钩（session_before_compact）的树+摘要；Claude Code 作为成熟产品，管理细节对用户更不透明。
  • 模型：Pi 通过 providers 可换（OpenAI / Anthropic / Google / 本地 Ollama）；Claude Code 绑定 Claude 模型。
  • 可定制：Pi 用 ExtensionAPI 深度重塑运行时；Claude Code 用 hooks、slash commands、插件、设置扩展。

选型决策框架，按你自己的约束走：

💡
  1. 想立刻干活、少折腾 → Claude Code。
  2. 想学懂 Agent 运行时内部、甚至自己改它 → Pi。
  3. 要深度定制工作流、把 harness 当积木组装 → Pi。
  4. 团队协作、生态成熟、少踩坑 → Claude Code。
  5. 想用非 Claude 模型、避免厂商锁定 → Pi。
  6. 要内置的安全/权限护栏、开箱即用的安全边界 → Claude Code。

两者不互斥：很多人用 Claude Code 做日常，用 Pi 做「理解与实验」。

✨

面试押题：如果考官问「你会怎么设计一个 coding agent harness」，用这课的分层来答——核心循环 + 最小工具集做地基，会话树管记忆，扩展机制管能力，权限用事件拦截做边界。Pi 正是这个思路的最小实现，Claude Code 则是在其上做了大量「产品化 + 内置能力」的取舍。能讲清「为什么这么分层、各层怎么取舍」，比背产品名值钱得多。

🛠️

动手

把决策树落到你自己身上：先写下一个你最常做的任务，再看它的约束是「时间/生态」还是「可控性/可移植性」，答案会自己浮出来。

💡
  • 若你的痛点是「赶进度、团队协作、少踩坑」→ 选 Claude Code 的完整助手形态。
  • 若你的痛点是「我要懂每一行、要接自己的模型/工具链、要可审计」→ 选 Pi 的最小核心 + 扩展。

要点回顾

  • 分歧在「核心该多大、能力放哪」：Claude Code 内置、Pi 外挂。
  • 权限/子 Agent/MCP：Claude Code 内置，Pi 靠扩展。
  • 模型：Pi 可换 provider，Claude Code 绑定 Claude。
  • 选型看约束：少操心选 Claude Code，想掌控/学透/换模型选 Pi。
