三 harness 终局对比与选型

Claude Code、Pi、Hermes 的取舍、组合用法与整条主线回顾

💡

为什么

走到这里，你已经见过三种 harness：产品化的 Claude Code、极简的 Pi、自进化的 Hermes。一个自然的问题是：到底该用哪个？

面试里，这通常不是「背参数」的题，而是系统设计取舍题。考官想听的是：你能不能说清三者在哪些维度上做了不同选择、这些选择分别优化了什么、又牺牲了什么。

先记住一句话：没有绝对更好，只有更适合当前约束。约束会变，答案也会变；真正可迁移的能力，是拆解与权衡，而不是对某个产品的忠诚。

🖼️

先看一张总表。注意它比较的是设计取向，不是版本号或跑分：

💡

读这张表的方法：不要逐格比「谁强」，而是看每一列整体在优化什么。Claude Code 优化「开箱即用的完成度」，Pi 优化「可控与可改造」，Hermes 优化「经验的长期复利」。

三者的差异，本质是三个问题的不同答案：

text
能力放在哪？   核心内置 ←→ 扩展外挂
经验放在哪？   项目配置 ←→ 会话状态 ←→ 记忆与技能文件
谁来演进？     产品团队 ←→ 你自己 ←→ 运行时自己
🧮

形式化

逐维度解读

定位与核心大小。 Claude Code 是旗舰产品，能力做进核心，换来开箱即用；Pi 把核心压到「循环 + 四个工具 + TUI + 会话树」，换来可理解、可改造；Hermes 的主循环仍是标准循环，但工具面更大（公开资料描述约 40 个内置工具），并在循环外挂了记忆与技能两条侧链。

记忆。 这是三者分歧最大的维度：

  • Claude Code 主要靠 CLAUDE.md 等项目上下文与会话内压缩，跨会话的「自动沉淀」不是它的重点。
  • Pi 把会话树持久化到本地，能续接、能分支，但不会自动把经验提炼成跨会话记忆。
  • Hermes 把记忆做成三层：工作记忆、情景记忆、技能记忆，并用 nudge 周期性整理。

模型与扩展。 Claude Code 绑定 Claude 模型，扩展靠 MCP、hooks、slash commands、skills、plugins；Pi 与 Hermes 都是 provider 无关，前者用 ExtensionAPI 重塑运行时，后者用 agentskills.io 风格 skills + MCP 扩展能力。

适合谁。 想立刻干活、团队协作、要成熟权限与生态，选 Claude Code；想学透、改造 harness、避免厂商锁定，选 Pi；要长期记忆、经验复用、定时自动化，选 Hermes。

⚠️

三者都在快速演进。「Hermes 有约 40 个工具」「Pi 只有四个工具」这类描述是当前设计取向的概括，不是永恒规格。选型前用你自己的任务做一次小验证，比背表格可靠。

选型决策树

按顺序问三个问题，先问约束，再问能力：

text
第一问：你现在的第一约束是「马上交付」吗？
  是 → Claude Code：产品化、生态成熟、开箱即用
  否 → 第二问

第二问：你需要理解/改造 harness，或避免厂商锁定吗？
  是 → Pi：最小核心、ExtensionAPI、provider 可换
  否 → 第三问

第三问：你需要跨会话记忆、经验复用、定时自动化吗？
  是 → Hermes：三层记忆、skills、cron
  否 → 回到第一问，按团队生态与维护成本选
✨

决策树不是判决书。真实选择常常是「主用一个，另两个补位」：例如日常交互用 Claude Code，实验与教学用 Pi，无人值守的巡检用 Hermes。

三者不互斥：组合用法

它们共享同一个 harness 内核，所以可以组合，而不是二选一：

  1. Claude Code 做日常，Pi 做理解与实验。 一个负责交付，一个负责把运行时拆开看。
  2. Hermes 做自动化层，Claude Code 做交互层。 定时巡检、记忆整理交给 Hermes；需要人盯着改代码时用 Claude Code。
  3. 共享纯文本工件。 MEMORY.md、SKILL.md、CLAUDE.md 都是 Markdown，可以把项目约定、操作手册沉淀成团队资产；但不同 harness 的技能格式不完全通用，迁移时需要适配。
  4. 能力通过 MCP 复用。 把内部系统包成 MCP server，三家都能接，避免为每个 harness 重写集成。
💡

组合的边界是权限与成本。每多一个 harness，就多一套凭证、日志与预算；组合的前提是你能说清「哪类任务归谁」。

整条主线回顾

把整条主线连起来看，这是一条从「模型怎么工作」到「怎么选运行时」的路径：

text
0 全景地图：先看整张地图
1 Transformer：模型内部怎么算
2 大模型怎么用：提示、采样、Function Calling
3 Agent 入门：模型 + 工具 + 循环，规划、记忆、评测
4 Harness 抽象：运行时循环与上下文工程
5 Claude Code：产品化的旗舰 harness
6 Pi：极简 harness
7 Hermes：自进化的 harness
8 Multica：把多个 harness 编成团队
9 RAG 检索增强（支线）：让模型用上外部资料

5 / 6 / 7 是同一层的三个分支，不是三个进阶等级：

  • Claude Code 告诉你「一个成熟产品会把哪些能力做进核心」；
  • Pi 告诉你「核心最小可以小到什么程度，扩展如何补位」；
  • Hermes 告诉你「经验如何外置成文件，让 harness 自己变强」。

三条线合起来，你得到的是一个可迁移的拆解框架：loop、context、tools、memory、extension、permissions。换一个新产品，你也能用这六个维度快速定位它。

🛠️

动手

做一次十分钟的选型练习。不要抽象讨论，用你手头真实的任务：

text
任务 1：____________________
首要约束：时间 / 可控 / 记忆与自动化 / 团队协作
候选：Claude Code / Pi / Hermes / 组合
理由：____________________
验证方式：用一个小任务跑 30 分钟

再补一张迁移检查表：

✨
  • 我的项目约定是否写成了纯文本（CLAUDE.md / MEMORY.md）？
  • 我的关键流程是否有 SKILL.md，还是只存在某次对话里？
  • 我是否依赖了某个 harness 的私有格式？换一家要改多少？
  • 我是否把「工具能做什么」和「模型该做什么」分清了？

如果四个问题里有两个以上答不上来，先别急着换工具——先把工件整理成可迁移的形式，换任何 harness 都会更轻松。

要点回顾

  • 三者分别优化：开箱即用的完成度（Claude Code）、可控与可改造（Pi）、经验的长期复利（Hermes）。
  • 选型先问约束：交付优先、改造优先、还是记忆与自动化优先。
  • 三者不互斥，可按「交互层 / 实验层 / 自动化层」组合，靠 MCP 与纯文本工件复用能力。
  • 主线 0→1→2→3→4→7；真正可迁移的是 loop、context、tools、memory、extension、permissions 六维拆解框架。
