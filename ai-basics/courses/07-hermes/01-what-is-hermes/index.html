L0第 1 课

Hermes 是什么

一个把学习写进 Markdown 的自进化 harness：不改权重，也能越用越顺手

💡

为什么

学完 Claude Code 和 Pi，你已经见过两种极端：一个把能力做进产品，一个把核心做到最小。Hermes 走第三条路——让 harness 自己积累经验。

先看一个熟悉的痛点。你今天花半小时教会 Agent：「这个仓库用 pnpm，不要用 npm；提交前先跑 pnpm test；日志格式必须是 JSON。」明天开新会话，它又忘了，你再说一遍。上下文窗口是易失的：会话结束，经验就蒸发。

Hermes 的主张很朴素：把学习外置成人类可读的文件。不是改模型权重，不是偷偷微调，而是把「事实」写进 MEMORY.md、USER.md，把「做法」写进 SKILL.md。下次会话，这些文件被重新读进上下文，同一个基座模型就显得更懂你。

✨

一句话：模型不变，harness 变；权重不变，文件变。

🖼️

可视化

三个 harness 的定位，可以放在一条「能力与经验放在哪」的轴上：

💡
  • Claude Code：产品化的旗舰 harness。计划模式、子 Agent、MCP、hooks、权限、skills 开箱即有，目标是「拿来就能干活」。
  • Pi：极简 harness。核心只有循环、四个工具、TUI 与会话树，目标是「小到你能理解并改造」。
  • Hermes：自进化的 harness。主循环仍是标准循环，但把记忆与技能沉淀成文件，目标是「同一个模型越用越顺手」。

注意三者的差别不在「会不会调工具」，而在经验放在哪、归谁所有。Claude Code 的经验多沉淀在产品能力与项目配置里；Pi 把状态交给会话树和你的扩展；Hermes 把经验显式写成一堆你能打开、能 diff、能删掉的 Markdown。

⚠️

Hermes 仍在快速演进。本节描述的是它的设计取向与公开资料中的稳定特征；具体命令、目录与默认值，请以你安装的版本为准。本课说的 Hermes，指 Nous Research 开源的 Hermes Agent（MIT 许可、Python 实现的一个 Agent 运行时），不是单指同名的 Hermes 模型系列。

🧮

形式化

先把「自进化」定义清楚，避免和微调混为一谈。

💡

自进化（self-improving）= 运行时把可复用的经验写成外部工件，并在后续运行中读回。 它不改变模型参数，只改变模型每次看到的上下文与可调用的技能。

三种「让 Agent 变强」的路径，成本与可审计性完全不同：

text
路径 A：改权重（预训练 / 微调 / RL）
  优点：能力内化，推理时不占上下文
  缺点：贵、慢、不可解释、难以按项目隔离

路径 B：改上下文（提示词 / 检索 / 记忆文件）
  优点：即时生效、人类可读、可版本化
  缺点：占上下文、依赖检索质量

路径 C：改工具与技能（SKILL.md / MCP）
  优点：把流程固化，减少重复推理
  缺点：技能会过时，错误也会被复用

Hermes 主要走 B 和 C。它的「学习」因此有三个很好的工程属性：

  1. 可审计：打开文件就能看到它记住了什么、学会了什么。
  2. 可修正：写错了直接改，或让它在下次使用时打补丁。
  3. 可迁移：文件是纯文本，能进 Git、能 review，也能带到另一个模型上。

代价也同样明显：记忆会占上下文，技能会过时，错误一旦写进文件就会复利。第 3、4 课会分别展开这两面。

从架构上看，Hermes 没有发明新的 Agent 范式。它仍是一个 Python 实现的 harness：组装上下文 → 调模型 → 分发工具 → 回填结果 → 循环。真正的差异在于循环之外挂了两条侧链：记忆写入与技能沉淀。

💡

面试时可以把三者概括为：Claude Code 是「产品化」，Pi 是「最小化」，Hermes 是「经验外置化」。三者共享同一个 harness 内核，分歧在工程取舍。

🛠️

动手

第一次使用 Hermes，不必急着让它写代码。先做一个「让它记住你」的小实验，观察文件是否真的出现。

text
第 1 轮（新会话）
你：这个项目用 pnpm，提交前必须跑 pnpm test。
Hermes：明白，我会记住。

第 2 轮（另一个新会话）
你：帮我改一下登录页的按钮样式。
Hermes：好的。按项目约定，我先确认 pnpm 与测试命令……

如果它真的「记住」了，你应该能在数据目录里找到类似这样的文件（目录名与层级以你的版本为准）：

text
<data-dir>/
  MEMORY.md      # 项目背景、关键决策、当前进度
  USER.md        # 你的身份、偏好、沟通风格
  skills/
    <skill-name>/
      SKILL.md   # 一个可复用的工作流
✨

验证方法：先看 USER.md 里有没有你的偏好，再看 MEMORY.md 里有没有「pnpm / 测试命令」这类项目事实。能读到，才算真记住；只嘴上说「记住了」，不算。

要点回顾

  • Hermes 是 Nous Research 开源的 Python Agent，模型/provider 无关，定位 self-improving。
  • 自进化不是改权重，而是把学习外置成 MEMORY.md、USER.md、SKILL.md。
  • 三个工程属性：可审计、可修正、可迁移；代价是上下文占用与错误复利。
  • 三者定位：Claude Code 产品化，Pi 最小化，Hermes 经验外置化。
