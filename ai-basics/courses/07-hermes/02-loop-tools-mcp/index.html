L1第 2 课

Loop、工具与 MCP

自进化没有改变主循环：一轮请求如何走完模型、工具与回填

💡

为什么

「自进化」听起来像魔法，但拆开看，Hermes 底下仍是那个你熟悉的 harness 循环：组装上下文 → 调模型 → 工具分发 → 结果回填 → 继续。

为什么要先讲循环？因为自进化是循环的副作用，不是另一套运行时。记忆在循环中被读出，技能在循环中被加载，nudge 在循环计数到阈值时触发。你不理解循环，就无法判断：一次任务为什么慢、为什么贵、为什么工具选错了、为什么记忆没被召回。

这一节把 Hermes 的主循环、工具面与 MCP 接入讲清楚。它和 Pi、Claude Code 的循环没有本质差别，差别在工具更多、上下文更厚、侧链更多。

自进化发生在主循环之外：工具结果回填与最终回复之后，再由侧链写入记忆与技能。

🧮

形式化

把循环写成伪代码，只有四个动作：

text
收到用户消息
loop:
  context = system_prompt + memory_snapshot + skill_index + history
  response = model(context, tools)
  if response 没有 tool_call:
      return response.text
  for call in response.tool_calls:
      result = dispatch(call.name, call.args)
      history.append(tool_result(result))

关键点：模型只负责决策，harness 负责执行与记账。工具调用失败不是异常终止，而是一条可被模型阅读的结果；模型看到错误后可以换参数、换工具或放弃。这也是 Agent 能从错误中恢复、进而沉淀技能的前提。

公开资料描述 Hermes 通常内置约 40 个工具，覆盖这些类别（具体清单随版本变化）：

💡
  • 文件与代码：读、写、编辑、列目录、搜索代码。
  • 终端与进程：执行命令、管理长任务、查看输出。
  • 网络：抓取网页、搜索、发 HTTP 请求。
  • 记忆：读写 MEMORY.md / USER.md，做全文检索。
  • 技能：列出、加载、创建、修补 SKILL.md。
  • 委派：创建子 Agent、等待结果、汇总。
  • 调度：注册 cron 任务、查看任务状态。
  • MCP 桥接：把外部 server 暴露的工具挂进统一命名空间。

MCP（Model Context Protocol） 是这里最重要的扩展点。它把「外部系统」标准化成一组可发现的工具：数据库、浏览器、工单系统、内部 API，都可以由独立进程暴露，再被 Hermes 当成普通工具调用。对循环而言，MCP 工具和内置工具没有区别——都是 dispatch(name, args) 的一个分支。

但工具变多不是免费的。四个典型挑战：

  1. 上下文预算：每个工具的名称、描述、参数 schema 都要进提示词。40 个工具可能吃掉可观的 token，记忆和对话的空间被挤压。
  2. 选择准确率：名字相近的工具容易选错，描述写得含糊会放大这个问题。
  3. 权限面：能执行终端、能发网络请求、能写文件，组合起来就是一条完整的攻击面。
  4. 不可信输出：工具返回的网页、Issue 评论、日志都可能包含 prompt injection，必须当作数据而不是指令。
⚠️

工具越多，越需要「最小权限 + 明确边界 + 可观测日志」。Hermes 的记忆与技能写入前会做注入与敏感数据扫描，失败则回滚；但这不是万能保险，关键操作仍应有人类审查或沙箱。

🛠️

动手

第一步，让 Hermes 自己报一次工具清单。这比翻文档更能反映你当前版本的真实能力：

text
你：列出你当前可用的工具，按类别分组，并标出哪些来自 MCP。
Hermes：我会先读取工具注册表，再按文件、终端、网络、记忆、技能、委派、调度分组……

第二步，接入一个 MCP server。下面是常见的配置形状，仅作示意；字段名、启动方式与路径以你的版本和 server 文档为准：

json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/project"]
    }
  }
}

第三步，验证三件事：

✨
  • 发现：新工具是否出现在工具清单里？
  • 调用：让它用新工具做一次只读操作，确认参数与返回正确。
  • 边界：故意让它访问范围外路径，确认权限或沙箱能拦住。

如果第三步失败，先查 MCP server 进程是否启动、路径是否被允许、工具描述是否被正确注册；不要一上来就怀疑模型。

要点回顾

  • Hermes 的主循环仍是「组装上下文 → 调模型 → 分发工具 → 回填结果」。
  • 公开资料描述约 40 个内置工具，覆盖文件、终端、网络、记忆、技能、委派、调度与 MCP。
  • MCP 把外部工具标准化接入，循环不变，但带来上下文、权限与信任成本。
  • 工具失败是可读的结果，不是异常终止；这是错误恢复与技能沉淀的前提。
