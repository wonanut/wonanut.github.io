Token 与词嵌入

文本如何变成模型能计算的数字

💡

为什么

神经网络只吃数字。要让模型处理文本，需要两步「翻译」：

  1. 分词（tokenize）：把文本切成一个个基本单位，叫 token；
  2. 嵌入（embedding）：把每个 token 映射成一个向量（一串数字）。

为什么不能直接给每个词编个号，比如「猫=1、狗=2、汽车=10086」？因为编号之间没有距离。编号 1 和 2 的差、1 和 10086 的差，说明不了任何语义关系。而向量天然带空间结构——语义相近的词，向量「住得近」，模型才能学到「猫 ≈ 狗，都远离汽车」。

✨

一个经典证据：训练好的词向量里，「国王 − 男人 + 女人 ≈ 王后」（king − man + woman ≈ queen）。这说明向量不仅编码了词义，还编码了关系。

🖼️

可视化

看下面这张词向量空间图（为方便画，只取了 2 维）：语义相近的词聚在一起，语义远的词离得远。这就是 embedding 的核心直觉——意义 = 位置。

💡

真实模型里 embedding 是几百到上万的维度（如 GPT 早期是 768，大的上万），而这里只画了 2 维。高维空间里词与词不仅「靠近/远离」，还能编码更丰富的关系（性别、单复数、时态等）。

🧮

形式化

第一步：分词。把文本 xxx 切成 token，再查词表（vocabulary）映射成 id：

x  →  [id1, id2, …, idn]x \;\to\; [\text{id}_1,\ \text{id}_2,\ \dots,\ \text{id}_n]x→[id1​, id2​, …, idn​]

例如「学习机器」可能被切成 ["学习", "机器"] 或更细的子词，再映射成 [2507, 3812] 这样的 id。

第二步：嵌入。查一个可学习的嵌入矩阵 WeW_eWe​（形状 vocab_size×dmodel\text{vocab\_size} \times d_{model}vocab_size×dmodel​），把每个 id 变成 dmodeld_{model}dmodel​ 维向量：

ei=We[idi]\mathbf{e}_i = W_e[\text{id}_i]ei​=We​[idi​]
💡

为什么用子词（subword，如 BPE）而不是整词或单字？

  • 整词：词表太大，且遇到没见过的词就抓瞎；
  • 单字：词表小，但损失了「词」的信息，序列变长；
  • 子词：折中——把「unbelievable」拆成 un + believ + able，既控制词表大小，又能拼出没见过的词。

现代大模型（GPT、Llama 等）都用某种子词算法。

要点回顾

  • 文本 → 分词（token + id）→ 嵌入（查 WeW_eWe​ 得向量）。
  • embedding 让语义相近的词在向量空间里靠近，编号做不到这一点。
  • 子词分词（BPE）在「词表大小」和「能处理新词」之间取得平衡。
