L1第 1 课

一张图看懂全景

模型、LLM、Agent、Harness、工具各自是什么，在主线里的位置在哪

💡

为什么

开始之前先看地图。

这套课有 10 门，术语又高度重叠：模型、LLM、Agent、harness、工具——很多人学到一半会卡在「这几个词到底谁包着谁」。地图的作用不是让你记住所有细节，而是先给你一个坐标系：以后遇到任何新概念，都能立刻判断它在哪一层、解决什么问题。

✨

一句话主线：模型给出下一个 token，LLM 让你会用它，Agent 让它会做事，harness 让 Agent 稳定地跑起来，具体 harness 决定你怎么用，团队层决定它们怎么一起干活。

所以学习顺序不是「十门课并列」，而是一路向下钻：先懂模型怎么工作，再懂怎么用模型，再懂 Agent 怎么循环，落到三种真实 harness 的取舍，最后看怎么把这些 harness 编成一支队。第 9 课是从 Agent 分出去的一条知识层支线：怎么让模型用上你自己的资料。

🖼️

可视化

悬停任意节点看它在主线中的位置；点击直接进入课程。

图分三层，从上到下依次变「工程」：

💡
  • 模型层（1–2）：Transformer 是「模型怎么工作」，大模型是「怎么用模型」。这一层解决的是理解与使用。
  • 运行时层（3–4）：Agent 是「模型 + 工具 + 循环」，harness 是「让这个循环稳定运行的运行时」。这一层解决的是抽象与机制。
  • 工具层（5–7）：Claude Code、Pi、Hermes 是三种真实 harness，分别代表产品化、极简、自进化三种取舍。这一层解决的是上手与选型。
  • 协作层（8）：Multica 不自带 harness，而是把 5–7 这些 CLI 编排成一个团队看板——任务、运行、验收记在同一个地方。这一层解决的是多人多 Agent 的协作。
  • 知识层（9）：RAG 讲「模型不知道的东西怎么补」——把外部资料切分、索引，按需检索后拼进上下文，并评测检索与回答质量。它依赖 2 与 3，和 4–8 并行，属于可选进阶。

注意 5 / 6 / 7 是平行的：它们都建立在第 4 课之上，彼此没有先后；三条路线在 7 的第 6 课汇聚成一次终局对比。第 8 课再往上抽一层——它不教新的 harness，而是教怎么把前三种（以及另外二十多种 CLI）放进团队协作。第 9 课不在 harness 行里，它是从 Agent 分出去的知识层支线：学完 2、3 就能读，不读它也不影响主线。

🧮

形式化

把五个词各给一个可操作的定义，后面每门课都会反复用到：

💡
  • 模型（model）：一个参数化的函数，输入上下文，输出下一个 token 的概率分布。
  • LLM（大语言模型）：在海量文本上预训练出来的超大模型；能力来自规模 + 数据 + 训练目标。
  • Agent：以目标为导向、能自己决定下一步的系统。最小公式是 Agent=LLM+Tools+Loop\text{Agent} = \text{LLM} + \text{Tools} + \text{Loop}Agent=LLM+Tools+Loop。
  • Harness：Agent 的运行时。它负责调用模型、分发工具、回填结果、管理上下文与会话，并在合适的时候停下来。可以写成 Harness=Loop+Context+Permissions+Session\text{Harness} = \text{Loop} + \text{Context} + \text{Permissions} + \text{Session}Harness=Loop+Context+Permissions+Session。
  • 工具（tool）：模型可以请求调用的外部能力，比如读文件、跑命令、搜索网页、调 API；通过 schema 描述参数。

把这些拼起来，一个「能用的 AI 产品」大致是：

Product≈Model+Harness+Tools+Context\text{Product} \approx \text{Model} + \text{Harness} + \text{Tools} + \text{Context}Product≈Model+Harness+Tools+Context

关键洞察：模型本身不执行任何东西。它只输出「我想调用 read 工具，参数是 README.md」这样的结构化意图；真正读文件、把结果拼回上下文、决定要不要继续的，是 harness。这就是第 4 课的核心。

⚠️

面试里最常见的混淆：把「模型会调用工具」说成「模型执行了工具」。准确说法是：模型提出工具调用，harness 执行并回填结果。

🛠️

动手

用地图做一次「定位练习」。打开上面的全景图，按顺序回答三个问题：

  1. 如果我想知道「为什么模型会算错数」，该去哪门课？——第 1 课，因为要理解 token 与概率生成。
  2. 如果我想知道「怎么让模型稳定地读文件、改代码」，该去哪门课？——第 3、4 课，Agent 循环与 harness。
  3. 如果我想选一个每天用的 coding agent，该去哪门课？——第 5–7 课，三种 harness 的对比与选型。
  4. 如果我想让整个团队和一堆 Agent 在同一条任务上协作，该去哪门课？——第 8 课，Multica 的工作区、运行时与小队。
  5. 如果我想让模型回答内部文档里的问题，并给出可核对的引用，该去哪门课？——第 9 课，RAG 的切分、检索、拼装与评测。

然后写下一句你自己的目标，越具体越好。例如：「两周内能自己写一个 50 行的 harness，并说清 Claude Code 的权限模型」。

✨

目标写得越具体，后面越容易判断「这节要不要精读」。地图不是装饰，是用来做取舍的。

要点回顾

  • 主线：模型 → LLM → Agent → Harness → 三种具体 harness → 编排它们的团队层。
  • 五个词的分层：模型/LLM 是能力，Agent 是形态，Harness 是运行时，工具是外部手脚。
