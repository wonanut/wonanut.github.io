ReAct 循环

Reason → Act → Observe：Agent 的心跳，也是所有 harness 的核心

💡

为什么

第 1 课说 Agent 的核心是「循环」。这一课把这个循环拆到最小单位，它的名字叫 ReAct。

ReAct 来自 Yao 等人 2022 年的论文《ReAct: Synergizing Reasoning and Acting in Language Models》。它解决了一个此前悬而未决的问题：光想不做（只会推理，接触不到真实世界）和光做不想（只会调工具，不会思考）都不够好。

  • 光想不做 = Chain-of-Thought：模型一步步推理，但推理可能基于错误记忆，产生幻觉；
  • 光做不想 = 纯工具调用：模型只会机械执行，不会停下来判断「这一步对不对」。

ReAct 的答案是：把「推理」和「行动」交织在一起——每走一步，先想（Reason），再动（Act），然后观察结果（Observe），据此再想下一步。这正是今天几乎所有 Agent（Pi、Claude Code、Hermes）的底层心跳。

🖼️

先用一个可逐步播放的循环视角，走一遍「查北京、上海的天气并比较」：每一步都问自己——这是模型想的、模型说的，还是 Agent 真正做的？

循环在「想 → 动 → 看」之间反复，直到模型给出 Final Answer；最大步数、超时与用户中断是兜底终止条件。

ReAct：LLM 每轮先推理再行动，Agent 负责执行与喂回；Thought/Action/Observation 交替，直到可作答。

关键点在 Thought → Action → Observation 的交替：LLM 不是一次性把所有工具都调了，而是「查完北京 → 观察结果 → 才决定下一步查上海」。而中间的编排、执行、喂回，全由 Agent 完成——LLM 自始至终只在「想下一步」。

🧮

形式化

ReAct 的三个动作：

💡
  • Thought（推理）：模型分析当前处境，决定下一步做什么。这是纯内部思考。
  • Action（行动）：模型发起一个对外动作——调用工具，或输出最终答案。
  • Observation（观察）：动作的真实结果（工具返回值），喂回模型。

循环的伪代码（这就是「harness loop」的最小形式，也是 Pi/Claude Code 底层在跑的东西）：

text
transcript = [user_request]
while not done:
    next = model(transcript)        # ① 模型产出下一步：文本 或 工具调用
    transcript.append(next)
    if next is tool_call:
        result = execute(next)      # ② harness 真正执行工具
        transcript.append(result)   # ③ 结果喂回 transcript
    elif next is final_answer:
        done = True                 # ④ 模型给出最终答案，终止
    elif steps >= MAX_STEPS:        # ⑤ 兜底：超步数强制终止
        done = True

终止条件（面试常考）：一个循环必须有办法停下来。常见四种：

💡
  1. 模型输出终止标记：模型判断「任务完成」，产出 final answer / stop token。
  2. 达到最大步数：harness 设置上限（如 50 步），防止死循环。
  3. 用户中断：人按 Ctrl-C 或点停止。
  4. 超时：单步或整体耗时超限。

为什么这个循环「贵」？ 回到第 1 课的「模型无状态」——每轮循环都要把整个 transcript 重新喂给模型。跑 10 步，模型就看了 10 次越来越长的上下文。这带来两个后果：

⚠️
  • token 开销线性增长：步数越多，每步越贵（成本 = 步数 × 平均上下文长度）。
  • 上下文终将塞满：上下文窗口是有限的，跑久了必须「压缩」旧内容——这正是第 5 课「记忆与上下文」要解决的。

这就是为什么「把循环做得又稳又省」是一门大学问，也是为什么 Pi 这类 harness 的源码里，压缩（compaction）和上下文管理占了这么大比重。

🛠️

动手

手动跑一遍 ReAct。任务：「查一下现在的 Python 最新版本号」。假设你只有两个工具：web_search(query) 和 read_web(url)。写出每一轮的 Thought / Action / Observation：

💡
  • Round 1 — Thought：「我不知道最新版本，需要查。」Action：web_search("Python latest version")。Observation：「官方页面显示 3.13 已发布」。
  • Round 2 — Thought：「搜索结果可能有误，最好去官网确认。」Action：read_web("python.org/downloads")。Observation：「页面显示 latest = 3.13.0」。
  • Round 3 — Thought：「两个来源一致，可以作答。」Action：Final Answer「Python 最新稳定版是 3.13.0」。

体会一下：如果只用 CoT（光想不做），Round 1 就卡住了——模型「以为」自己知道版本，可能直接编一个错答案。ReAct 的价值，是每一步的推理都建立在真实观察之上。

要点回顾

  • ReAct = Reason + Act：推理与行动交织，而非先想完再动或只动不想。
  • 三个动作：Thought（决定下一步）→ Action（调工具）→ Observation（看结果）。
  • harness 循环：模型产出下一步 → 执行 → 喂回 → 直到终止标记/超步数/中断/超时。
  • 循环「贵」在每轮重读整个 transcript，这是压缩与上下文管理的根源。
