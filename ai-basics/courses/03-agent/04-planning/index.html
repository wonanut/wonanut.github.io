L1第 4 课

规划与反思

任务分解、CoT、Plan-and-Solve 与 Reflexion：让 Agent 走对路

💡

为什么

简单任务（查天气、改一行代码）靠 ReAct 直接冲就行。但复杂任务——「重构整个测试套件」「写一份行业调研」——不能走一步看一步，否则很容易在错误的方向上越走越远。

这就是「规划（planning）」要解决的：在动手前/中，把大任务拆成可执行的小步，并让 Agent 对失败做出反思和修正。

规划不是新东西，但它在 Agent 语境下特别重要，因为 Agent 的每一步都是真金白银的 token 和时间。走错一步，不只是慢，还可能把环境改坏（删错文件、发错请求）。所以「先想清楚再动手」在 Agent 里有真实的工程价值。

🖼️

对比之下，纯 ReAct 是「没有地图的边走边问路」——每一步都重新判断方向，短期灵活，但缺一个全局计划兜底。

🧮

形式化

① 从隐式规划到显式规划

💡
  • CoT（Chain-of-Thought，Wei et al. 2022）：让模型「把思考过程说出来」。这是隐式规划——推理链本身就是规划，但不输出可检查的「计划清单」。
  • Plan-and-Solve（Wang et al. 2023）：先让模型显式列出一个计划（第 1、2、3 步…），再逐条执行。计划是结构化的、可检查的，中间还能改。
  • ReAct（Yao et al. 2022）：上一课讲的「边想边做」。它的 Thought 是短程规划，缺长程视角。

三者不是互斥的——现代 Agent 常常是**「先 Plan-and-Solve 定大纲，再用 ReAct 执行每一步」**：外层有全局计划，内层有局部探索。

② 反思（Reflection）：从失败中学习

光是「规划」不够，因为计划常常是错的。Reflexion（Shinn et al. 2023）提出：Agent 失败后，不直接重试，而是先反思失败原因，生成一段「口头反馈」，存进记忆，下次引用。

text
# 一次失败后，Reflexion 生成的 verbal feedback（存进 episodic memory）
"尝试用 requests 库抓取时被反爬拦截了。
 下次应该：先检查 robots.txt，改用带 User-Agent 的请求头，
 并在解析前先打印返回的 HTML 确认结构。"
💡

关键洞察：反思把「一次失败」变成「一条可复用的经验」。没有反思，Agent 每次都在同一个坑里摔；有了反思，第二次遇到类似情况时，记忆里的 feedback 会提醒它换个做法。

③ 更高级的规划范式（面试加分项，点到为止）

💡
  • Tree of Thoughts（Yao et al. 2023）：不只走一条推理链，而是同时展开多条、互相评估、保留最优，像下棋的搜索树。
  • ReWOO / 结构化分解：把「推理」和「执行」进一步分离，减少模型反复自我确认的 token 浪费。

这些范式的共性：用「更多的思考」换「更少的错误执行」。

④ 一个必须讲的工程权衡：规划 vs 试错

⚠️

规划不是免费的。每多一步「思考」，就多花 token、多花延迟。于是有了这条权衡：

  • 规划多：前期想得细，执行更稳，但 token 成本高、响应慢——适合高风险、不可逆的任务（改数据库、发请求）。
  • 规划少：直接试，快、便宜，但容易跑偏、要反复重试——适合低风险、可逆的任务（读文件、搜索）。

优秀的 Agent（和优秀的 Agent 工程师）会在两者之间按任务风险动态切换，而不是一律「先想 10 步」。

🛠️

动手

给同一个任务写两条轨迹，感受「隐式规划」和「显式规划」的区别。任务：「找出这个仓库里所有 TODO 注释，并分类整理成报告」。

💡

轨迹 A（纯 ReAct，隐式）：grep 一下 → 发现有 20 个 TODO → 再想想怎么分类 → 读几个文件 → 发现有些 TODO 已经过期 → 再 grep 过期标记 → …… 边走边发现，可能遗漏类别。

轨迹 B（Plan-and-Solve，显式）：先列计划——① grep -rn TODO 找全部 ② 读文件判断每个 TODO 的状态（有效/过期/模糊） ③ 按模块分组 ④ 写报告。然后逐步执行，每一步都有预期产出，偏差一眼可见。

差别在哪？B 的每一步都有「预期产出」，所以哪一步漏了、哪一步偏了，一眼就能定位；A 则要靠运气，容易漏。

再练一个「反思」：假设轨迹 B 第 ① 步 grep 返回 0 个结果。Reflexion 会反思什么？（提示：可能是关键词写错了，或文件被 .gitignore 了。）把这句 feedback 写下来，存进你的「经验库」。

要点回顾

  • 隐式规划（CoT）vs 显式规划（Plan-and-Solve）：显式计划可检查、可修改。
  • Reflexion：失败 → 反思 → verbal feedback 入记忆 → 下次复用。
  • 高级范式（ToT 等）：用更多思考换更少错误执行。
  • 核心权衡：规划 vs 试错，按任务风险动态选择。
