L1第 1 课

什么是 Agent

从 LLM 到 Agent：加一个循环，模型就从「说话」变成「做事」

💡

为什么

先问一个朴素的问题：大模型（LLM）会「做事」吗？

不会。一个裸的 LLM 只会做一件事——预测下一个 token。你给它一个 prompt，它生成一段文本，仅此而已。它不能查天气、不能读写文件、不能发网络请求、不能执行代码。它「知道」很多，但「做」不了任何事。

那 ChatGPT、Claude Code、Pi 这些能查资料、改代码、跑命令的系统，到底多了什么？

答案就一句话：

Agent = 模型 + 工具 + 一个把结果喂回模型的循环。

  • 模型：大脑，负责「下一步做什么」的决策；
  • 工具：手脚，真正去执行动作（查 API、读文件、跑命令）；
  • 循环：把工具的执行结果再喂给模型，让它根据真实结果继续决策，直到任务完成。

这个「循环」是 Agent 区别于普通 LLM 应用的唯一分水岭。去掉循环，模型只是会聊天；加上循环，模型开始「做事」。

工程上，这个「循环」由一段叫 Agent 运行时（harness） 的代码实现——它是用户唯一对话的对象，LLM 和工具都藏在它后面、由它编排。下面这张图里的「Agent」，指的就是这个运行时。

如果没有中间的 Agent 和工具调用，LLM 就只能「猜」天气——这就是幻觉的来源之一。Agent 的价值，在于用真实世界的反馈替代模型的猜测。

🧮

形式化

定义：Agent 是一个「能自主选择行动、执行行动、并观察结果来推进目标」的系统。形式上，它由三部分组成：

  1. 模型：给定上下文，产出「下一个动作」——可能是一段文本，也可能是一次工具调用（第 3 课）。
  2. 工具：把「动作」变成真实的副作用——查数据、改文件、发请求。
  3. 循环（harness）：反复执行「模型决策 → 执行 → 喂回结果」，直到满足终止条件（第 2 课）。

一个关键事实：模型是无状态的。

模型每次被调用，看到的只是「当前上下文」——一段对话历史 + 工具结果。它不记得上一次循环里自己做了什么。是外部的 harness 把整个 transcript 拼好、喂回给它。所以「循环」「记忆」「上下文管理」这些，全都是 harness 的职责，不是模型自带的。这个认知会贯穿整门课，也是第 4 课（Harness 抽象）的地基。

自主性光谱：不是所有「用了 LLM 的系统」都是 Agent。按 Anthropic《Building Effective Agents》（2024-12）的区分：

💡
  • 纯 LLM：一问一答，无工具、无循环（如「翻译这句话」）。
  • Chatbot：多轮对话，但只做问答，不改变外部世界。
  • Workflow（工作流）：LLM 和工具按预定义的代码路径编排——步骤是程序员写死的，LLM 只负责每步里的内容生成。可预测、好调试。
  • Agent：LLM 动态决定自己的流程和工具使用——「下一步走哪」是模型运行时判断的。灵活，但难预测、难调试。

面试时最容易暴露「没真懂」的说法，是把「工作流」和「Agent」混为一谈。区分标准只有一个：路径是预先写死的，还是模型运行时自己决定的。

为什么要用 Agent 而不是 Workflow？

⚠️

Workflow 适合流程固定的任务（审批、抽取、模板生成），因为可预测、成本可控。Agent 适合步骤事先无法枚举的任务（「帮我修这个 bug」「调研 X 并写报告」）——你不知道需要几步、会用到哪些工具，只能让模型边走边看。代价是：不可预测、可能跑偏、成本高（第 6 课讲评测与护栏）。

🛠️

动手

判断下面三个系统，哪个是 Workflow，哪个是 Agent：

💡
  1. A：一个「把 PDF 发票抽成结构化 JSON」的系统，固定四步：OCR → 找金额 → 找日期 → 输出 JSON。每步都调用 LLM，但步骤顺序是代码写死的。
  2. B：一个「帮我重构这个仓库的测试」的工具，你只给目标，它会自己决定先看哪些文件、改哪些、跑什么命令、发现失败再回头修。
  3. C：一个客服机器人，规则树决定「用户问退货 → 走退货流程」，每步用 LLM 生成自然语言回复。

答案是：A 和 C 是 Workflow（路径固定，LLM 只填空），B 是 Agent（路径由模型运行时决定）。

记住这个判断心法：「如果每一步都提前知道，就是 Workflow；如果下一步要等上一步的结果才知道，就是 Agent。」
