预训练、后训练与对齐

三个阶段各解决什么问题：从下一 token 预测到有用、守规矩的助手

💡

为什么

同一个模型，为什么既能续写文章、又能听懂指令、还会拒绝有害请求？这不是一个训练阶段完成的，而是三棒接力：

  1. 预训练（pretraining）：读海量文本，学会语言、世界知识和推理的「原材料」，但本质仍是一个续写器；
  2. 后训练（post-training / SFT）：用指令—回答样本，教它「按人的要求回答」，而不是继续续写；
  3. 对齐（alignment）：用人类偏好与安全数据，教它「什么该做、什么不该做」。

理解这三阶段，你才能判断一个模型问题该从哪里修：是基座能力不足，还是指令跟随没训好，还是安全边界没对齐。

✨

一句话分工：预训练给能力，后训练给用法，对齐给边界。 三者缺一不可，也不能互相替代。

🖼️

可视化

把三阶段看成一条流水线：数据先变成「会说话的模型」，再变成「听指令的助手」，最后变成「守规矩的助手」。

三阶段接力：预训练学能力，SFT 学用法，对齐学边界。

💡

三阶段分别解决什么问题：

  • 预训练：解决「不会说话、没有知识」——让模型具备语言与世界的统计结构。
  • 后训练（SFT）：解决「会续写但不会听指令」——把基座变成对话助手。
  • 对齐（RLHF/DPO）：解决「会回答但未必有用、诚实、安全」——让输出符合人类偏好。
🧮

形式化

预训练的目标是自回归下一 token 预测。给定序列 x1,…,xTx_1,\dots,x_Tx1​,…,xT​，最大化真实下一 token 的似然：

LPT=−∑t=1Tlog⁡pθ(xt∣x1:t−1)L_{\text{PT}} = -\sum_{t=1}^{T}\log p_\theta(x_t \mid x_{1:t-1})LPT​=−t=1∑T​logpθ​(xt​∣x1:t−1​)

它不需要人工标注，规模可以做得极大。规模通常指三件事：参数量、训练 token 数、算力。经验上它们与损失呈幂律关系（scaling laws），所以「更大的模型 + 更多的数据」在相当长一段时间里是最可靠的提升手段。

涌现能力（emergent abilities）值得单独提一句：某些能力在小模型上接近随机，规模跨过某个阈值后突然变好。但学界也发现，部分「涌现」可能是指标选择造成的假象——换个连续指标，曲线可能是平滑的。面试时别把「涌现」说成玄学，它是规模带来的能力相变，且测量方式会影响结论。

**后训练（SFT）**用指令—回答对做监督微调，损失通常只算回答部分：

LSFT=−∑t∈answerlog⁡pθ(yt∣instruction,y1:t−1)L_{\text{SFT}} = -\sum_{t \in \text{answer}}\log p_\theta(y_t \mid \text{instruction}, y_{1:t-1})LSFT​=−t∈answer∑​logpθ​(yt​∣instruction,y1:t−1​)

SFT 主要教格式、语气、任务分解方式，并不能可靠地注入新知识。数据质量远比数量重要：一条精心写的示范，常常胜过一百条模板化问答。数据太窄还会带来灾难性遗忘，所以要混入一部分通用数据。

对齐常见两条路线：

  • RLHF：先训练奖励模型（reward model）拟合人类偏好，再用 PPO 优化策略；表达能力强，但流程复杂、训练不稳定。
  • DPO：直接用「偏好回答 vs 拒绝回答」的成对数据优化策略，不需要显式奖励模型；实现简单、更稳定，是当前常用的对齐基线。

对齐的目标常概括为 HHH：helpful（有用）、honest（诚实）、harmless（无害）。取舍也很真实：

⚠️
  • 对齐税（alignment tax）：对齐后某些基准能力可能略降。
  • 奖励黑客（reward hacking）：模型学会讨好奖励模型，而非真正解决问题。
  • 过度拒绝：安全训练过头，正常请求也被拒。
  • 谄媚（sycophancy）：模型倾向于附和用户，而不是指出错误。

还有一个常见误解：后训练不会让模型「知道」训练截止后的新事实。需要时效性知识时，正确做法是检索（RAG）或工具调用，而不是指望微调。

🛠️

动手

假设你要做一个「电商客服助手」，把需求拆到三个阶段：

💡
  • 预训练：选一个开源基座或直接用厂商的基座模型。它已经会中文、懂常识，但不能直接上线——它可能继续编客服话术。
  • 后训练：准备 1k–10k 条高质量客服对话，统一语气、退换货政策口径、回答结构。目标是「像客服一样说话」。
  • 对齐：准备偏好数据，明确「不得承诺未授权的退款」「不得泄露其他用户信息」「不确定时转人工」。目标是「知道边界」。

用数据格式直观感受一下。SFT 样本是一条完整示范：

text
{"messages": [
  {"role": "system", "content": "你是电商客服，语气简洁礼貌。"},
  {"role": "user", "content": "订单 123 什么时候到？"},
  {"role": "assistant", "content": "我先帮你查物流，请稍等。"}
]}

DPO 样本则是一对「更好 / 更差」的回答：

text
{"prompt": "能直接给我退款吗？",
 "chosen": "需要先确认订单状态，我帮您提交售后申请。",
 "rejected": "可以，马上退，无需任何条件。"}

练习：下面三个故障分别该由哪个阶段负责？

  1. 模型知识停在两年前，答不出昨天的新政策；
  2. 模型能答题，但总是长篇大论、不按客服话术；
  3. 模型会答应任何退款请求，包括明显越权的。

答案：1 靠检索/工具补知识，不是训练阶段能单独解决；2 是 SFT 数据与格式问题；3 是对齐与权限约束问题。

要点回顾

  • 预训练：下一 token 预测，靠规模获得语言与世界知识，本质是续写器。
  • 后训练：SFT 用指令—回答对教格式与任务分解，不可靠地注入新知识。
  • 对齐：RLHF 用奖励模型 + PPO，DPO 用偏好对直接优化；目标是 HHH，但存在对齐税、奖励黑客、过度拒绝与谄媚。
