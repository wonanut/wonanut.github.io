L2第 4 课

采样：temperature 与 top-p

从 logits 到 token：temperature 调尖锐度，top-k/top-p 砍尾巴

💡

为什么

模型每生成一个 token，并不是直接「选一个词」，而是先给词表里每个 token 打一个分数（logit），再把分数变成概率分布，最后按分布抽一个。

这套「打分 → 概率 → 抽样」的机制，决定了输出的确定性与创造性：

  • 同样的提示，为什么有时答案一样、有时完全不同？
  • 为什么调低 temperature 代码更稳，调高 temperature 文案更有创意？
  • top-k 和 top-p 到底在砍什么？

理解采样，你才能有意识地控制模型行为，而不是把参数当玄学乱调。

🖼️

💡

怎么玩：

  • logits：模型原始打分，可正可负；softmax 之前它们不是概率。
  • temperature：缩放 logits；越低分布越尖，越高越平。
  • top-p：按概率从高到低累加，累计到 ppp 就截断，剩下的 token 被标为「截断」。
  • 采样一次：按重新归一化后的概率抽一个 token；多抽几次能直观看到随机性。

先试一组固定的 logits [2, 1, 0.5, -1]，对比 temperature 0.2 与 1.5 的概率条，再把 top-p 从 0.9 拉到 0.5，观察哪些 token 被砍掉。

🧮

形式化

设词表第 iii 个 token 的 logit 为 ziz_izi​，温度为 T>0T > 0T>0，则采样概率为：

pi=exp⁡(zi/T)∑jexp⁡(zj/T)p_i = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}pi​=∑j​exp(zj​/T)exp(zi​/T)​

temperature 的作用：

  • T=1T = 1T=1：不改变原始分布；
  • T<1T < 1T<1：logits 被放大，分布更尖，高概率 token 更容易被选中；
  • T>1T > 1T>1：logits 被压平，低概率 token 也有机会；
  • T→0T \to 0T→0：等价于贪心（每次选最大 logit）。

以 logits [2, 1, 0.5, -1] 为例，T=1T=1T=1 时概率约为 [0.609, 0.224, 0.136, 0.030]；T=0.5T=0.5T=0.5 时约为 [0.842, 0.114, 0.042, 0.002]。温度降低后，第一名从 61% 升到 84%，分布明显更「果断」。

top-k：只保留概率最高的 kkk 个 token，其余置零，再归一化。kkk 是固定数量，简单直接，但当分布很尖时 kkk 太大、很平时 kkk 太小。

top-p（nucleus sampling）：把 token 按概率降序排列，取累计概率首次达到 ppp 的最小集合 SSS：

S=min⁡{S′:∑i∈S′pi≥p}S = \min\left\{S' : \sum_{i \in S'} p_i \ge p\right\}S=min{S′:i∈S′∑​pi​≥p}

只在这个集合里采样，再归一化。top-p 的保留数量随分布自适应：模型很确定时只留一两个，犹豫时自动多留一些。

组合顺序通常是：先按 TTT 缩放并 softmax，再应用 top-k / top-p 过滤，最后在剩余 token 上重新归一化并采样。顺序很重要——top-p 必须在 temperature 之后，因为温度会改变累计概率的形状。

⚠️
  • 贪心（greedy）：每步取 argmax，适合抽取、分类、代码补全等要求稳定的任务；但容易重复、缺乏多样性。
  • 束搜索（beam search）：同时保留 BBB 条候选序列，按累计对数概率选最优；常用于翻译等离线 seq2seq，计算开销大，且输出偏「安全、平庸」。
  • temperature = 0 不等于绝对确定：浮点误差、批处理与并行计算都可能带来细微差异；需要强确定性时要固定种子并接受实现差异。
🛠️

动手

做三组对照实验，记录现象：

  1. 温度对照：logits 固定为 [2, 1, 0.5, -1]，top-p 设 1.0。分别用 T=0.2T=0.2T=0.2 与 T=1.5T=1.5T=1.5 连点 10 次「采样一次」，看结果分布。
  2. 核采样对照：T=1T=1T=1，top-p 分别设 0.9 与 0.5。观察 0.5 时是否只剩一个或两个 token 存活。
  3. 极端分布：把一个 token 的 logit 拉到 3，其余压到 -3，再看温度是否还能带来多样性。

工程上，采样参数通常这样传：

text
{"temperature": 0.2, "top_p": 0.9, "max_tokens": 512}

一个经验法则：要稳定就降温度，要多样性就升温度；不想要离谱 token 就加 top-p。 但不要同时把 temperature 和 top-p 都调得很极端——两个约束会叠加，效果难以预测。

要点回顾

  • 生成流程：logits → 除以温度 → softmax → top-k/top-p 过滤 → 重新归一化 → 采样。
  • temperature 控制分布尖锐度：低则确定，高则随机。
  • top-k 保留固定数量；top-p 保留累计概率达到 p 的最小集合，数量自适应。
  • 贪心/束搜索适合稳定或离线任务；temperature 为 0 也未必绝对确定。
