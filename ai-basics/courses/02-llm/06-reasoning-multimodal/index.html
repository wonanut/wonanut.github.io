推理与多模态

在推理时多花算力，以及把图像、音频、视频变成 token

💡

为什么

大模型的两条前沿，一条向内、一条向外：

  • 向内：推理（reasoning）。不再只靠训练时堆算力，而是在推理时让模型多想一会儿——写更长的思维链、采样多条路径、用验证器挑答案。这叫 test-time compute。
  • 向外：多模态（multimodal）。让模型不只看文本，还能看图、听音频、看视频；这些输入最终都要被编码成 token，塞进同一个上下文。

这两条路线共同决定了今天模型的能力边界，也共同放大了成本与延迟问题。理解它们，你才知道什么时候该用「会思考的模型」，什么时候该用「能看图的模型」，以及它们的代价是什么。

🖼️

可视化

推理模型的一种典型用法是多采样 + 投票：同一个问题让模型走多条推理路径，再选最一致的答案。

test-time compute：不在训练时加大模型，而是在推理时多采样、多验证。

💡

两种常见策略：

  • 自一致性（self-consistency）：采样多条推理链，对最终答案做多数投票；适合答案可比较的任务。
  • Best-of-N + 验证器：生成 N 个候选，用奖励模型或规则验证器挑最好的；验证器质量决定上限。

代价也很直接：N 倍 token、N 倍延迟。不是所有任务都值得。

🧮

形式化

Test-time compute 的核心思想：模型能力不只由参数决定，也由「推理时愿意花多少计算」决定。常见手段包括长思维链、多采样投票、验证器重排、树搜索。经验上，在困难推理任务上，增加推理算力可以换来准确率提升，但存在边际收益递减：简单题多采样是浪费，超难题目多采样也可能只是重复犯错。

思维链（CoT） 是让模型显式写出中间步骤。它之所以有效，一部分原因是把复杂计算拆成多个较简单的 token 预测，降低单步难度。但要注意：CoT 文本是模型生成的，不一定忠实反映内部计算；它可以是「事后合理化」。所以 CoT 能帮助模型，不等于能作为可靠的审计记录。

推理模型通常经过强化学习训练，倾向于生成长篇内部推理，再给出结论。使用时有几个工程要点：

⚠️
  • 推理 token 通常按输出计费，长思考会显著推高成本与延迟。
  • 很多 API 提供 reasoning_effort 或思考预算参数；不是越高越好，要按任务调。
  • 简单分类、格式转换、固定抽取通常不需要推理模型，用小模型更快更便宜。
  • 「让普通模型写 step by step」和「用推理模型」不是一回事：后者经过专门训练，通常更稳，但代价更高。

多模态输入如何变成 token：

  • 图像：切成固定大小的 patch（如 16×1616 \times 1616×16 像素），每个 patch 经视觉编码器变成一个向量，再投影到语言模型的 token 空间。图像 token 数约为：
nimg≈Hp×Wpn_{\text{img}} \approx \frac{H}{p} \times \frac{W}{p}nimg​≈pH​×pW​

之后还可能做池化或压缩。例如 1024×10241024 \times 10241024×1024 的图、patch 为 16，则 64×64=409664 \times 64 = 409664×64=4096 个 patch；若 2×22 \times 22×2 池化，约剩 1024 个视觉 token。

  • 音频：波形先转成频谱特征（如 mel 频谱），按帧切分后由音频编码器变成 token 序列；时长越长，token 越多。
  • 视频：按固定帧率采样画面，每帧按图像方式编码，再叠加音轨；token 成本随帧数与分辨率快速上升。

多模态让模型能处理更丰富的输入，但没有改变底层机制：所有模态最终都是 token，都要占上下文预算。一张高分辨率图片可能等价于几千个文本 token，长视频更是如此。

⚠️

能力边界仍然存在：多模态模型仍会幻觉（可能描述图中不存在的物体）、仍受上下文限制、对细粒度 OCR、空间关系、长视频时序的理解也不稳定。关键场景要用规则、OCR 工具或人工复核兜底。

要点回顾

  • Test-time compute：推理时多花算力，手段包括长 CoT、自一致性、Best-of-N 与树搜索，收益递减。
  • 推理模型经过专门训练，推理 token 计入输出成本；简单任务不必用。
  • 多模态输入最终都变成 token：图像切 patch、音频按帧编码、视频采样帧，均占上下文预算。
  • 多模态仍会幻觉，受上下文与细粒度理解限制，关键场景要工具与人工兜底。
