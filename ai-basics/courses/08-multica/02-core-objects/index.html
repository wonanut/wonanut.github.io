L0第 2 课

核心对象：工作区、任务、运行、运行时

六个概念撑起整套系统，关键是把「智能体」「运行」「运行时」分清

💡

为什么

Multica 的界面第一次打开会有点让人发怵：侧边栏里有工作区、任务、项目、智能体、小队、自动化、运行时、收件箱……十几个入口。

但真正需要理解的对象只有六个，它们的关系是一条清晰的链：

💡

工作区 → 任务 → 运行 → 运行时；智能体和 skill 挂在这条链上。

新手最容易混的是三个长得很像的词：智能体（agent）、运行（run）、运行时（runtime）。混了这三个词，后面所有排障都做不下去——因为「它为什么没动」的答案，往往就取决于你问的到底是哪一个。

🖼️

可视化

先把六个对象按「谁是什么」摆开，用一句话各自定位：

💡
  • 工作区 Workspace：团队共同工作的独立范围，一切工作和配置都在其中，人和智能体混在一起协作。
  • 任务 Issue：一项要完成的工作，以及围绕它积累的描述、讨论、状态和历史。日常工作的基本单位。
  • 项目 Project：把相关任务组织在同一个目标下，可绑定仓库、目录等资源供执行时使用。
  • 智能体 Agent：一份可复用的配置——名称、指令、模型、skill、Access、运行时。不是一个常驻进程。
  • 运行时 Runtime：执行实际发生的地方——连接到 Multica 的电脑，以及那台电脑上的 AI 编程工具。
  • 运行 Run：智能体一次具体执行的记录。一次触发 = 一次运行。

再看它们怎么连起来：

text
                工作区（容器，人和智能体都在里面）
                                │
        ┌───────────────────────┼───────────────────────┐
        │                       │                       │
     任务 Issue ──── 属于 ──── 项目 Project        Skill（可复用能力包）
        │                                               │ 挂载
        │ 触发（分配 / @提及 / 对话 / 自动化）            │
        ▼                                               ▼
     运行 Run ──── 在 ──── 运行时 Runtime ◄──── 配置 ──── 智能体 Agent
        │                   （你的电脑 + CLI）
        └─ 结果与日志写回任务时间线

关键的观察：智能体是身份，运行时是工位，运行是工时记录。一个运行时可以承载多个智能体；一个智能体可以产生多次运行。

🧮

形式化

把三个易混概念做成对照表，这张表建议直接背下来：

text
概念      回答的问题            生命周期              失败时的表现
--------  --------------------  --------------------  ------------------------------
智能体    谁来做、按什么方式做  长期存在，可归档      归档后不再接收新工作，历史保留
运行时    在哪台电脑执行        进程级，随守护进程    离线时运行排队等待，不失败也不丢失
运行      这一次干得怎么样      单次，有起止         failed / cancelled，可重试

从对象关系再补三条规则，它们解释了后面所有行为：

  1. 运行结束 ≠ 任务完成。 执行日志里显示「已完成」，只说明这一次执行结束了。任务仍然可以继续讨论、补充要求或再次触发智能体。任务是否完成，看它自己的状态。
  2. 一个任务可以有多次运行。 失败重试、换智能体接手、被 @ 追加处理，都产生新的运行记录，旧记录不会被覆盖。
  3. 离线不等于删除。 智能体或运行时显示离线/归档是两件事。已入队的运行会等运行时恢复；只有「已归档」才意味着它不能接收新工作。

还有两个容易漏的边界规则：

⚠️
  • 智能体没有收件箱，也收不到 @all。对智能体的 @ 提及是一次执行触发，不是一条通知。
  • 修改任务的负责人或状态不会停止已经开始的运行。想中断，就在执行日志里停掉那条具体的运行。
💡

工作区角色分 owner、admin、member。owner 和 admin 能查看并管理所有智能体，但不能绕过 Access 去运行别人设为「仅自己」的智能体——权限和可见性是两条独立的轴。

🛠️

动手

不装任何东西，先用 CLI 把这些对象读一遍。CLI 的好处是：界面上能点的，CLI 里都能调，而且 --output json 让对象结构一目了然。

bash
multica auth status          # 当前连的哪个服务、哪个用户、token 还有效吗
multica workspace list      # 工作区列表
multica issue list          # 任务列表
multica issue list --output json | head -40
✨

--output json 只写 stdout，警告和确认信息走 stderr。不要把 2>&1 合进去再解析——那会让一次其实成功的写操作看起来像失败，然后你就重试了一次，产生重复数据。

然后拿一条真实任务，把三个概念对齐一次：

bash
multica issue get <issue-id>            # 任务：目标、状态、负责人
# 在界面上打开同一任务右侧的「执行日志」
# 每一行 = 一次运行：触发来源 / 执行智能体 / 状态

# 观察：这条任务历史上有几次运行？分别是哪次触发产生的？

判断练习：看到「Engineer 在工作」这条状态条，它反映的是智能体的工作负载（来自运行），不是可用性（来自运行时）。列表里这两类状态是并排展示的，别读成一个。

🎯
