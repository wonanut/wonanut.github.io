Multica 是什么

一个开源自托管的团队工作区：智能体像同事一样接任务、报进展、交代码

💡

为什么

你已经学了 Claude Code、Pi、Hermes 三种 harness。它们都默认同一件事：一个人，一个终端，一个会话。

问题出在第三个「一」上。终端会话是易失的——关掉就没了。于是真实工作里会出现这样的场景：早上你在 Claude Code 里让 Agent 改了登录页；下午换个标签页开 Codex 修接口；晚上发现两边的改动打架，而当初为什么这么改，只存在你自己的脑子里。智能体越加越多，你越忙，因为你成了唯一的上下文总线。

Multica 换了一个比喻：不把智能体当工具，而是当队友。

💡

一句话：智能体是队友，任务是看板上的卡片，代码在你的机器上跑。

它不是又一个更聪明的 Agent，而是 harness 外面的一层协作系统。它不驱动模型，不代替 CLI，只负责回答四个问题：谁来做、做什么、做到哪了、做完谁验收。

🖼️

可视化

为什么需要这一层？把一个理想化的单人开发者和一个多人团队的差异摆在一起看：

💡
  • 单终端模式：上下文在会话里 → 会话结束即蒸发 → 想接着干，必须重新解释。
  • 聊天式协作：上下文在群聊里 → 关键决定淹没在消息流 → 新成员要爬几百条记录。
  • Multica 模式：上下文挂在任务上 → 任务本身带着描述、讨论、执行记录和产出 → 换人、换智能体都不用重讲。

名字本身说明了取向。Multica = Multiplexed Information and Computing Agent，向 1960 年代的 Multics 致意——那是第一个真正实现分时的系统：多个人共享一台机器，每个人都像独占它。Multica 的主张是，把「分时」重新做一遍，只不过这次被多路复用的「用户」，既是人，也是能自己干活的智能体。

它还和前面三门课构成一组对照，这一点值得先摆清楚，免得你以为这是第四个 harness：

⚠️
  • Claude Code / Pi / Hermes 是 harness：负责一次执行——组装上下文、调模型、调工具、回填结果。
  • Multica 是工作区：不实现 harness，而是调度你已经装好的 harness。它支持 26 种智能体 CLI，换 provider 就是切个下拉框。

换句话说，学完这门课你不会有「第四个要学的 Agent」，而是学会怎么把已有的 Agent 编队。这门课放在第 8 位，正是因为前面 7 门课讲的都是「单个 harness 怎么工作」，这里才开始讲「多个 harness 怎么协作」。

🧮

形式化

先把边界钉死，这是理解 Multica 的前提。

💡

Multica 记录并协调工作，连接的电脑负责执行。

这条边界在云端和自托管里完全相同，可以做成一张对照表：

text
Multica 服务端                     你的电脑（运行时）
------------------------------     ------------------------------
工作区、任务、评论、状态           AI 编程工具及其凭据
智能体配置与 skill                 代码目录与本地文件
运行状态、执行记录、结果            实际的文件修改与命令执行

所以代码不出门。智能体跑在你自己的笔记本或云主机上，用的是你本来就登录好的 claude、codex、cursor-agent。Multica 服务端看到的是一串进度和结果，而不是你的仓库。

有一个例外必须记住：

⚠️

保存到智能体 custom_env 的内容会存放在 Multica 服务端，执行时下发给运行时。不希望离开你电脑的 secret，不要写进 custom_env。

技术栈上，它是一套相当标准的现代全栈系统：

text
Web      Next.js 16（App Router）
桌面端    Electron，复用 Web 的 UI 包
移动端    Expo / React Native
iPhone/iPad
后端      Go（Chi router, sqlc, gorilla/websocket）
数据库    PostgreSQL 17
执行层    本地守护进程，拉起任意一种受支持的 Agent CLI

许可证是 Multica License——Apache 2.0 全文并入，外加针对托管服务、商业嵌入和品牌标识的附加条件。自托管、改代码、在它之上做东西都可以；但如果你打算拿它做对外收费的托管产品，需要先读 LICENSE 原文。

🛠️

动手

先别急着注册。本地摸一下这个项目，感受它的体量，比读十篇介绍都快。

bash
git clone --depth 1 https://github.com/multica-ai/multica.git
cd multica
ls
# apps/      desktop docs mobile ui-lab web
# packages/  core plugin-sdk ui views
# server/    Go 后端：daemon / dispatch / issueworkflow ...
cat README.zh.md | head -60

接着翻一遍三条最值得读的文档，它们决定了你后面会不会踩坑：

bash
README.zh.md          # 功能全景，每一项都链到对应文档
VISION.zh.md         # 为什么叫 Multica，它想变成什么
CLI_AND_DAEMON.md    # 守护进程与 CLI，最好的排障手册

echo $RUNTIME        # 你打算用哪台机器跑智能体？
✨

在动手前先明确一件事：你有几台机器可以当运行时？ 一台笔记本就够跑通全流程，但如果你打算让它干重活（跑测试、构建），一台专用机器或容器会省心很多。第 6 课会专门讲这个边界的风险。
