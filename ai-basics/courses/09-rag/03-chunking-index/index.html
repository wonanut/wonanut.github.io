L1第 3 课

切分与索引

块多大切、重叠留多少、元数据怎么用，以及混合检索的融合

💡

为什么

嵌入的输入不是整篇文档，而是块（chunk）。原因很实在：整篇文档的向量会把太多主题平均掉，检索出来「什么都沾一点、什么都不准」；而且上下文窗口也塞不下整篇。

所以切分不是预处理里的小事，它直接决定了检索的下限：

  • 块太大：一个块里混着三四个主题，向量被平均，命中率下降；拼进上下文又浪费预算。
  • 块太小：一句完整的规定被拦腰切断，「前半句在块 A、后半句在块 B」，模型拿到半句也无法回答。
  • 重叠太少：答案恰好落在切线附近时，两块都只有半截。
  • 重叠太多：同一内容被重复召回，既费预算又容易让模型重复作答。

这一节就把这几组权衡摆到台面上。

🖼️

💡

三个观察点：

  • 每块字数：决定索引的最小语义单位。中文常见起点是 300–500 字，英文 200–400 token，再按你的文档结构调整。
  • 块间重叠：常见取块长的 10%–20%，用来兜住边界；超过一半就开始明显浪费。
  • 块数与冗余：块数越多，检索越精细，但索引与 rerank 成本越高。

更好的切法往往不是「按固定字数硬切」，而是按结构切：先按标题、段落、列表项切，再对超长段落做二次切分。这样每个块天然是一个完整语义单元。

🧮

形式化

设文档长度为 LLL，块长为 SSS，重叠为 OOO（0≤O<S0 \le O < S0≤O<S），块数近似为：

N≈⌈L−OS−O⌉N \approx \left\lceil \frac{L - O}{S - O} \right\rceilN≈⌈S−OL−O​⌉

块内冗余比例为：

ρ=OS\rho = \frac{O}{S}ρ=SO​

例如 S=400S=400S=400、O=80O=80O=80，则 ρ=20%\rho=20\%ρ=20%：每 5 个块的字数里，有 1 个块是重复内容。O→SO \to SO→S 时冗余爆炸，O=0O=0O=0 时边界信息全部丢失。

结构切分的优先级通常是：

  1. 按文档层级（章 → 节 → 段）切，保留标题路径；
  2. 超长段落按句子边界切，绝不从句子中间切；
  3. 对表格、代码块整体保留，不拆散；
  4. 给每块带上元数据：来源文件、标题路径、更新时间、权限标签。

元数据不是装饰，它让检索可以做过滤（只搜我有权限的文档）和溯源（回答里的 [1] 点回原文）。

混合检索：向量检索擅长语义，BM25 擅长精确词与稀有术语（错误码、产品型号）。两者结果用 RRF（Reciprocal Rank Fusion） 融合，不依赖分数尺度是否可比：

RRF⁡(d)=∑r∈检索器1k+rank⁡r(d)\operatorname{RRF}(d) = \sum_{r \in \text{检索器}} \frac{1}{k + \operatorname{rank}_r(d)}RRF(d)=r∈检索器∑​k+rankr​(d)1​

其中 kkk 通常取 60。只看排名，不看原始分数，所以两路检索可以各用各的度量。

⚠️

切分的天花板问题：如果答案需要同时引用块 A 和块 B，而它们在索引里互不相邻，任何单块检索都拼不出完整答案。解法是小到大地检索（small-to-big）：用小块检索保证命中，返回时扩展成它的父段落；或者对块做邻接扩展（取命中块前后各一块）。

🛠️

动手

做两组对照，记录现象：

  1. 固定重叠 0，块长 40 / 80 / 140：哪一档最可能把关键句切断？把切点附近的文字读出来找证据。
  2. 固定块长 80，重叠 0 / 20 / 40：块数与冗余如何变化？重叠 40 时有没有出现重复内容？

然后给一个块补上元数据。真实索引里的块通常长这样：

要点回顾

  • 切分决定检索下限：太大被平均，太小被切断。
  • 重叠取 10%–20% 兜边界，半块以上就开始浪费。
  • 优先按结构切，保留标题路径与元数据，便于过滤与溯源。
  • 向量 + BM25 用 RRF 融合；跨块答案用 small-to-big 或邻接扩展。
