L1第 5 课

进阶检索

rerank、查询改写、多路召回与 agentic RAG，按收益排优先级

💡

为什么

基础的「向量 top-k」在简单问答上够用，但真实问题常常更麻烦：

  • 问题口语化、信息不全（「那个报销的事到底怎么弄」）；
  • 答案需要跨两三个文档拼起来（「A 产品的退款政策和 B 产品的差异」）；
  • 同义词与专有名词混杂，单路召回覆盖不到；
  • top-20 里明明有正确块，却排在第七位没进上下文。

这一节讲的就是这些情况下「怎么把正确材料找回来」。重要原则：每次只加一个组件，并用评测证明它值得那份额外延迟。

🖼️

可视化

最有效的一类升级是 agentic RAG：不再「检索一次就生成」，而是让模型在循环里决定「还要不要查、查什么」。

agentic RAG：检索结果决定下一步查什么，而不是一次检索定生死

各技术的收益与代价：

💡
  • rerank（精排）：对 top-20 用更强的模型重排，通常收益最高、改动最小，延迟增加几十到几百毫秒。
  • 查询改写：把口语问题改写成 2–3 个检索式，或生成假想答案再检索（HyDE）；适合问题模糊的场景。
  • 混合检索：向量 + BM25 + RRF，专治错误码、型号、人名等精确词。
  • 元数据过滤：先按权限、时间、文档类型过滤再检索，兼顾安全与精度。
  • 多跳 / agentic：用多轮检索补全缺口，能力最强，但成本与延迟最高，也最难评测。
🧮

形式化

双塔（bi-encoder）vs 交叉编码器（cross-encoder）：

  • 检索阶段用双塔：查询与文档分别编码，文档向量可以离线算好，查询时只算一次、做 ANN，速度快。
  • rerank 阶段用交叉编码器：把「查询 + 文档」拼在一起送进模型，输出一个相关性分数。它能看到两者的交互，精度高得多，但无法预计算，只能对少量候选在线打分。

这就是标准的「宽召回 → 精排」两段式：

top⁡100⏟向量 + BM25 + RRF  →  top⁡5⏟rerank  →  拼装\underbrace{\operatorname{top}_{100}}_{\text{向量 + BM25 + RRF}} \;\rightarrow\; \underbrace{\operatorname{top}_{5}}_{\text{rerank}} \;\rightarrow\; \text{拼装}向量 + BM25 + RRFtop100​​​→reranktop5​​​→拼装

多查询（multi-query）：用模型把原问题改写成 mmm 个检索式，分别检索后按文档去重合并。它提高了召回，也放大了噪声，所以后接 rerank 效果最好。

HyDE：让模型先写一段「假想答案」，再用这段答案去检索。原理是「答案与文档更像，而问题与文档不像」——适合短问题、专业术语多的场景；代价是多一次生成。

多跳检索：有些问题无法一次检索解决（「A 的 CEO 毕业于哪所学校？」需要先查 A 的 CEO 是谁，再查此人教育背景）。判断标准很简单：问题里有没有需要先确定的中间实体。有就上多跳或 agentic，没有就别过度设计。

⚠️

别把复杂当高级。每加一个组件都会引入新的失败模式与延迟。推荐顺序：先修切分与元数据 → 加 rerank → 加混合检索 → 再考虑查询改写与 agentic。每一步都用同一套评测集对比，收益不显著就撤掉。

🛠️

动手

按收益/成本排一个升级路线，并写下每步的验证方式：

text
阶段 0  基线：向量 top-5 → 生成
      评测：recall@5、faithfulness

阶段 1  加 rerank：top-30 → cross-encoder → top-5
      验证：recall@5 不变或上升，答案准确率上升，P95 延迟可接受

阶段 2  加混合检索：向量 + BM25 → RRF → rerank
      验证：含错误码/型号的问题召回率上升

阶段 3  加查询改写：multi-query 3 路 → 去重 → rerank
      验证：模糊问题的 recall@5 上升，延迟与成本记录

阶段 4  agentic：允许模型在最多 2 轮内补查
      验证：多跳问题正确率上升；设置轮数上限与超时

选一条你现在最痛的查询类型（例如「问题太口语化」或「答案跨文档」），只做对应的一步，然后跑评测。不要一次上完所有组件——你无法知道是谁起了作用。

✨

一个实用的判断：如果 rerank 之后正确块能稳定进前 5，但答案仍然不对，问题在拼装或生成，不在检索。先别继续堆检索组件。
