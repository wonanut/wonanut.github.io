Harness 的职责

上下文、工具协议、权限、流式、会话：五块职责，少一块就出事故

💡

为什么

上一课把循环拆成了阶段。但阶段只是骨架，真正决定一个 harness 好不好用的，是它在每个阶段承担哪些职责。

一个常见的误解是：harness 只负责「把模型的 tool call 转给工具」。这只说对了五分之一。生产级 harness 至少承担五块职责：

  1. 上下文管理；
  2. 工具协议与分发；
  3. 权限；
  4. 流式；
  5. 会话。

这一课不只讲「做什么」，更讲「不做会怎样」。因为面试里区分「读过文档」和「真正写过」的，往往就是这些失败模式。

🖼️

🧮

形式化

五块职责逐一拆开。每一块都配一个「不做会怎样」，方便你在设计评审里讲清必要性。

1. 上下文管理

组装 active branch，决定哪些消息进入请求；做裁剪、摘要与压缩；维护可复用的前缀以命中缓存。

⚠️

不做会怎样：上下文溢出被 API 拒绝；旧指令与新指令冲突；每轮都全量重发导致成本失控；压缩时丢掉关键约束，模型开始改错文件。

2. 工具协议与分发

把工具定义成模型能理解的 schema；解析 tool call；校验参数；按名字查 registry；处理未知工具、超时与异常；把结果序列化回填。

⚠️

不做会怎样：模型编造不存在的工具；参数类型错误导致运行时崩溃；未知工具让循环卡死；异常没被转成 observation，模型永远不知道失败。

3. 权限

在工具真正执行前做策略判断：允许、拒绝、或询问用户；限制路径与命令；隔离沙箱；记录谁在什么时候执行了什么。

⚠️

不做会怎样：提示注入可以诱导模型执行破坏性命令；Agent 能读到不该读的密钥；没有审计记录，事故无法追溯。权限必须由 harness 强制，不能靠 system prompt 请求模型自觉。

4. 流式

把模型的 token 流增量转发给界面；在 tool call 出现时正确中断；支持用户取消；保证中断后会话状态可恢复。

⚠️

不做会怎样：用户要等整段生成完才看到反馈，体感极慢；无法中途停止；工具调用与文本渲染交错时出现乱序或重复。

5. 会话

持久化 transcript；支持恢复、分支与回放；处理并发请求与版本；记录每次运行的元数据。

⚠️

不做会怎样：进程崩溃就丢失全部工作；无法复现一次失败运行；不能从某个检查点分叉尝试别的方案；多人或多任务并发时互相覆盖。

需要强调边界：harness 不负责「任务该怎么规划」「答案对不对」。那是模型能力与上层框架的事。harness 的职责是让每一次模型调用与工具执行都可控、可观测、可恢复。这五块职责里，只有「工具协议」和「流式」紧贴模型 API；上下文、权限、会话都可以独立演进，这也是换 provider 时只需要动适配层的原因。

🛠️

动手

拿一个真实编码 Agent 做一次职责审计。假设它刚执行了「读取配置 → 修改配置 → 重启服务」：

💡
  • 上下文：重启日志有 2000 行，harness 是全量回填还是截断？截断后模型还能判断成功吗？
  • 工具协议：restart_service 的参数 schema 有没有校验？未知服务名返回什么？
  • 权限：修改生产配置前，是直接执行、拒绝，还是询问用户？
  • 流式：重启期间界面显示什么？用户能否取消？
  • 会话：如果重启把 Agent 自己所在的进程也杀了，状态存在哪里？
text
event: token          data: {"text": "我先检查配置"}
event: tool_start     data: {"name": "read_file", "input": {"path": "app.yaml"}}
event: tool_end       data: {"name": "read_file", "ok": true, "bytes": 812}
event: token          data: {"text": "配置里 port 是 8080"}
event: done           data: {"stopReason": "final"}

事件流里没有「模型」和「工具」的直接通信——所有事件都经过 harness。这正是「谁负责执行工具」的答案：harness 是唯一的执行者与状态持有者。

判断一个 harness 是否成熟，看它能否回答三个问题：工具失败时模型看得到吗？危险操作前有人拦吗？进程崩溃后会话还在吗？

要点回顾

  • 五块职责：上下文管理、工具协议与分发、权限、流式、会话。
  • 每块都有明确的失败模式；权限必须在执行前强制，不能靠提示词。
  • tool call 会中断流式文本，harness 负责拼装、执行、回填与恢复。
  • harness 管「怎么发生」，不管「该做什么、答得对不对」。
